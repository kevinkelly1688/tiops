## 1. 平台是什么

TiDB 运维平台（TiDB Ops）部署在 tiup 中控机上，提供四类能力：

| 能力 | 说明 | 对应页面 |
|---|---|---|
| 看 | 集群总览、拓扑架构、告警、慢 SQL、热点、诊断结论 | 集群总览 / 集群架构 / 智能诊断 / SQL 优化 / 热点与调度 |
| 查 | 排障向导、巡检、参数建议 | 故障排查 / 日常运维 |
| 改 | 重启、扩缩容、配置变更、主机维护、备份恢复；带审批、定时、审计 | 节点管理 / 变更排期 / 日常运维 |
| 装 / 发命令 | 中控机模式下：在页面里一键部署新集群（支持离线），向中控机发带护栏的命令 | 安装部署 / 中控机命令 |

**所有写操作都不会直接下发命令**：先由服务端**规划并做前置检查**，再按「风险 × 环境」走审批，最后经受限执行器（命令白名单 + 审批令牌）执行，全程写入带哈希链的审计日志。

**平台账号与 TiDB 数据库账号是两套独立的体系**：平台账号（用户名 / 口令 / 角色）只用于登录和使用本平台，在平台里创建账号不会在 TiDB 里创建用户，数据库账号也不能登录平台。平台访问集群用的是管理员配置的两个固定数据库账号（只读账号、运维账号）。

### 平台的运行模式

平台启动时有两种互斥的模式，**页面上无法切换**：

| 对比项 | 只读 / 回放模式 | 运维模式 |
|---|---|---|
| 登录 | 无登录，打开即看 | 必须登录，会话有超时 |
| 能做什么 | 只能查看 | 查看 + 提交变更 + 审批 + 审计 + 用户与角色管理 + 多集群 |
| 写操作按钮 | 部分页面的按钮可点，但只是**前端原型模拟，不会作用于集群** | 按角色权限启用 / 置灰，真实走服务端变更引擎 |

怎么判断：打开页面直接进入总览、顶栏没有「环境 / 写操作 / 用户名 / 退出」这组标签，是只读 / 回放模式；先出现登录页、登录后顶栏有这组标签，是运维模式。**正常的生产部署都是运维模式**，本文以运维模式为准。

## 2. 登录与账号

平台只支持**本地账号**，登录只认**用户名 + 口令**（不需要动态验证码）；没有 LDAP / SSO。账号由管理员在「用户管理」里创建。

### 2.1 登录步骤

1. 浏览器打开平台地址（向管理员或部署人员要），出现登录页。表单标题下有一个环境标签（生产 / 预发 / 测试），登录前先核对是不是你要登录的平台；**不同平台地址是各自独立的平台、各自独立的账号库**。
2. 输入用户名（不区分大小写）和口令（右侧「👁」可显示 / 隐藏）。键盘大写锁定开着时会有提示。
3. 点「登 录」或回车。成功后顶栏右侧出现：环境标签、「写操作已开启」或「只读」、「显示名 · 角色名」、「退出」。
4. 「记住用户名」只在浏览器本地保存用户名，**口令永不保存**；公共电脑不要勾选。

### 2.2 登录提示与处理

| 提示 | 原因 | 怎么办 |
|---|---|---|
| 用户名或口令错误 | 用户名不存在、口令错、账号已被禁用——平台故意不区分，防止被探测账号 | 核对用户名与口令；仍不行请管理员确认账号是否被禁用 |
| 登录失败次数过多，请在 HH:MM:SS 后重试 | 同一用户名**或**同一来源 IP 在 10 分钟内连续失败 5 次，被锁定 10 分钟 | 等到提示的时间；用户名维度的锁定管理员可在「用户管理」里「解锁」；**IP 维度的锁定只能等它自然结束** |
| 登录已过期或已在别处退出，请重新登录 | 空闲超过 30 分钟、满 8 小时、管理员禁用 / 改了你的角色 / 重置了你的口令、你在别处退出，或平台被重启 | 直接重新登录 |
| 无法连接后端 | 浏览器连不上平台（网络 / 代理 / 服务没启动） | 稍后重试；仍不行联系部署人员 |

锁定期间，**即使用户名和口令都对也会被拒绝**。经反向代理访问时，平台看到的来源 IP 往往是代理的地址，别人连续输错也可能连累你。

### 2.3 忘记口令、丢了 MFA

**本平台不提供邮件 / 短信自助找回**：

| 你的情况 | 怎么办 |
|---|---|
| 普通账号忘了口令 | 联系管理员，在「用户管理」里点你那一行的「重置口令」，用临时口令登录后立刻到「权限与审计 → 我的账号」改成自己的口令。重置会让你所有已登录的会话失效 |
| 管理员自己忘了口令 | 先看有没有另一名管理员能帮你重置；没有的话，由有中控机命令行权限的人**先停服务**，再执行命令行重置并启动服务（步骤见《运维部署手册》7.5） |
| 手机丢了 / 换了，动态验证码用不了 | 不影响登录，只影响提交生产高风险变更。请管理员对你「重置 TOTP」，再到「我的账号」重新绑定 |

### 2.4 口令、MFA 与会话的规则

| 项 | 规则 |
|---|---|
| 口令策略 | 至少 10 位、至少 3 类字符（大写 / 小写 / 数字 / 符号）、不得包含用户名、最长 128 位 |
| MFA（TOTP） | **不是登录方式**，只用于提交高风险变更时的申请人二次确认（默认只有「生产 · 高风险」，审批策略里可配）；6 位动态码，30 秒一换；同一时间窗内的验证码只能用一次 |
| 会话 | 空闲 30 分钟、绝对 8 小时过期；过期后任何操作回到登录页，重新登录即可 |
| 退出 | 顶栏「退出」，立即销毁会话 |
| 限速 | 每个用户写类请求每分钟 60 次，超过提示「请求过于频繁」 |

你会遇到的两种提示：在另一个标签页登录了别的账号后，原标签页操作提示「CSRF 校验失败」，**刷新页面**即可；通过反向代理访问却提示「拒绝跨站请求」，说明代理改写了 `Host` 头，请联系部署人员。

## 3. 界面速览

### 3.1 整体布局

- **左侧导航栏**：分「概览 / 诊断与优化 / 运维 / 平台配置 / 帮助」几组；左下角和标题下显示平台版本号（悬停显示提交与构建时间）。「平台配置」分组（用户管理、角色权限、集群接入）按权限显示。
- **顶栏**：页面标题 + **集群下拉** + 数据来源标签；右侧是「? 帮助」、主题切换（浅色 / 深色 / 护眼）、以及运维模式下当前集群的环境 / 写开关 / 你的角色 / 退出。
- **内容区**：随屏幕宽度自动撑满；窄屏（宽度不足 820 像素）时侧栏变成顶部横条。
- 页面底部显示网站备案号（如果管理员配置了）。

### 3.2 通用元素

| 元素 | 说明 |
|---|---|
| 数据横幅 | 页面顶部「回放数据」或「真实数据（只读）」，显示集群名与采集时间；有「N 项数据缺失」可展开看缺哪些；「立即刷新」强制重新采集（最短间隔 2 秒），页面每 30 秒自动刷新一次 |
| 抽屉 | 点击表格行 / 操作按钮从右侧滑出详情或提交面板；点「关闭 ✕」或按 `Esc` 关闭 |
| 复制按钮 | 命令块右上角的「复制」：把命令复制到剪贴板，**只复制不执行** |
| 提示（toast） | 屏幕顶部的短暂提示，如「已刷新」「已批准 CHG-0001」；失败原因也会在这里显示 |
| 主题 | 默认**浅色**；顶栏和登录页右上角可切换「浅色 / 深色 / 护眼」，选择保存在浏览器本地。护眼是柔和的豆沙绿底色，适合长时间值班 |
| 帮助 | 「? 帮助」按当前页面打开同名帮助；侧栏「使用帮助」打开帮助首页和全文搜索 |

### 3.3 徽标含义

| 徽标 | 含义 |
|---|---|
| 侧栏「集群总览」数字角标 | 当前非提示级别的告警数 |
| 侧栏「节点管理」数字角标 | 执行中 + 排队中的变更数 |
| 侧栏「变更排期」数字角标 | 待审批的变更数 |
| 侧栏「权限与审计」数字角标 | 等待**你**确认的双人复核提案数 |
| 低 / 中 / 高风险 | 变更风险等级（绿 / 橙 / 红） |
| 待审批 / 排队中 / 已排期 / 执行中 / 成功 / 失败 | 变更状态；已中止、已驳回、已取消、已过期为灰色终态 |
| 紧急 / 待复盘 | 紧急变更；紧急变更已结束但尚未填写复盘 |
| 通过 / 警告 / 异常 / 未采集 | 巡检与自检结果；「未采集」表示取不到数据，平台不会猜测 |

## 4. 多个集群与「环境」

运维模式下，一个平台可以同时管理**多个 TiDB 集群**（最多 20 个，由管理员在「集群接入」页接入）。每个集群有自己的**环境**：测试 / 预发 / 生产。要记住三件事：

1. **页面上看到的一切（总览、节点、变更、告警……）都属于「当前集群」**，也就是顶栏集群下拉里选中的那个。
2. **每个集群各管各的**：数据采集、变更与审批队列、写操作开关（含两名管理员确认）、变更窗口与冻结期、通知渠道、主机池、巡检结果。**全平台共用**的是：用户、自定义角色、审批策略、双人复核提案、审计日志、登录会话。
3. **环境 = 数据范围**：你在某个集群里有什么角色，由**该集群的环境**决定。你在一个集群的环境里没有角色，这个集群对你就**不可见**——下拉里没有它，直接访问得到的提示与「集群根本不存在」完全一样。

### 怎么切换集群

1. 看页面标题右边的集群下拉框，每个选项形如「预发集群（预发）」。下拉框的颜色按当前集群的环境着色（测试绿、预发橙、生产红）；当前集群是生产环境时，旁边还有红底白字的「生产环境」标签。
2. 选另一个集群，页面会**整页刷新**（有抽屉或未保存内容时会先弹出确认框）。刷新后环境标签、写开关状态、你的角色、页面数据都变成新集群的，你仍停留在原来的页面。
3. 你的选择记在这个浏览器里，下次打开自动回到它。

切换只是换视图，不改服务器上的任何东西，不用重新登录；但之后提交的变更、开的开关、改的设置都属于**新集群**。**动手前先看顶栏**：下拉框的颜色、生产环境标签，以及变更提交面板顶部的「集群 X」标签。

集群的两种接入方式（管理员在「集群接入」页操作）：

| 方式 | 能做什么 |
|---|---|
| 本机 tiup（「从本机 tiup 导入」） | 可做全部运维操作；写开关与审批照常 |
| 远程接入（手工添加，只填网络地址） | **只读**，平台碰不到它的 tiup / SSH，不能执行变更 |

## 5. 角色与权限

角色按**环境**授予（测试 / 预发 / 生产可以是不同角色，未单独设置的环境沿用「所有环境」）。一个人可有多个角色，**最终权限是这些角色能力的并集**；被禁用的账号一律没有任何权限。

### 5.1 内置的 7 个角色

| 角色 | 定位 |
|---|---|
| 访客 | 只读：看总览、拓扑 |
| 开发 | 业务开发：只看自己被授权的库的慢 SQL 与执行计划 |
| 值班 SRE | 值班：看全部、跑诊断巡检、申请实例级操作 |
| DBA | 变更执行：发起并执行扩缩容、配置、维护、备份等变更（经审批） |
| 审批人 | 把关：审批中 / 高风险变更；不能执行变更 |
| 管理员 | 平台管理：用户与角色、平台设置；**不能直接做集群变更，也不能审批变更** |
| 审计员 | 审计：只读审计日志并导出 |

图例：✔ 直接允许；审 = 可以发起，但要按「风险 × 环境」走审批；范 = 仅限被授权范围；— = 无。

| 能力 | 访客 | 开发 | SRE | DBA | 审批人 | 管理员 | 审计员 |
|---|---|---|---|---|---|---|---|
| 查看总览 / 拓扑 | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |
| 查看慢 SQL / 执行计划（含 SQL 文本） | — | 范 | ✔ | ✔ | ✔ | ✔ | — |
| 运行诊断 / 巡检 / 只读命令 / 告警静默 | — | — | ✔ | ✔ | ✔ | ✔ | — |
| 导出巡检报告 | — | — | ✔ | ✔ | ✔ | ✔ | — |
| 单实例操作 / 滚动重启 | — | — | 审 | 审 | — | — | — |
| 扩缩容 / 升级 | — | — | — | 审 | — | — | — |
| 配置变更 | — | — | — | 审 | — | — | — |
| 主机维护 | — | — | — | 审 | — | — | — |
| 备份 / 恢复 | — | — | — | 审 | — | — | — |
| 审批中风险变更 | — | — | — | — | ✔ | — | — |
| 审批高风险变更 | — | — | — | — | ✔ | — | — |
| 修改平台设置 | — | — | — | — | — | ✔ | — |
| 开启 / 关闭写操作开关 | — | — | — | — | — | 审 | — |
| 用户与角色管理 | — | — | — | — | — | ✔ | — |
| 查看审计日志 | — | — | — | — | ✔ | ✔ | ✔ |
| 导出审计日志 | — | — | — | — | — | — | ✔ |
| 中控机命令：执行 / 批准（中控机模式） | — | — | — | — | — | ✔ | — |

**职责分离要点：**

- 管理员不能执行集群变更，也不能审批变更；审批人不能发起变更；申请人不能审批 / 驳回自己的变更，同一人不能对同一变更重复审批。
- 变更的**取消 / 中止 / 确认人工步骤**只有申请人本人或内置的 DBA 角色能做；**填写事后复盘**只有申请人能做。
- 访客和审计员看不到任何慢 SQL；开发只能看到管理员为其授权的库的慢 SQL。
- 有「查看审计日志」能力的角色（审批人、管理员、审计员）还能**只读**查看「用户管理」与「角色权限」两页。
- 在「权限与审计 → 我的账号」可以看到你当前环境下拥有的全部能力。

### 5.2 用户的最终权限怎么算

1. 先确定**当前集群的环境**下生效的角色列表。如果用户在该环境上被「单独设置」了角色，就**只用**这个列表，完全不看「所有环境」的角色；没有单独设置，才用「所有环境」的列表。**切换到另一个环境的集群，生效的角色就跟着换**。
2. 再把这个列表里所有角色的能力合并（并集），每项能力取最强的授予方式（✔ > 审 > 范 > 无）。
3. 每个请求都按当前最新的角色判定，管理员改了你的角色，几秒内页面按钮就会跟着变化。

### 5.3 自定义角色

内置 7 个角色不够用时，管理员可以新建**自定义角色**（一组能力，每项选「允许 / 需审批 / 范围内」）。主要限制：最多 50 个；角色 ID 创建后不能改（2–32 位，小写字母开头）；必须含「查看总览」；「用户与角色管理」「写操作开关」「修改平台设置」只属于内置管理员；操作者只能授予自己拥有的能力；还有成员的角色不能删除。修改**即时生效**，不需要成员重新登录。自定义角色的成员同样**不能代别人**取消或中止变更（只认申请人本人或内置 DBA）。

## 6. 各页面能做什么

下面按侧栏顺序简介每个页面。每页的逐步操作、参数说明、后果与常见问题，在页面里按「? 帮助」查看。

### 6.1 集群总览（所有角色）

值班第一屏：一眼看清集群「有没有出事、哪里在变化、容量还能撑多久」。本页只读。

- 4 张 KPI 卡片：QPS、P99 延迟、连接数、存储使用（含容量预测）。
- 最近 60 分钟的 QPS 与 P99 趋势、数据库时间（DB Time）按 SQL 类型的构成。
- 「实例健康矩阵」：TiDB / TiKV / PD 每个实例的状态、CPU、内存、磁盘。

## 7. 一次变更怎么走：预览、审批、执行、中止

```
预览（规划 + 前置检查）→ 提交 →（待审批 → 逐级审批）→ [已排期] → 排队中 → 执行中 → 成功 / 失败 / 已中止
                                  └→ 驳回 / 取消 / 过期（终态，不执行）
```

### 7.1 生命周期

| 阶段 | 发生什么 | 你要注意 |
|---|---|---|
| 1. 预览 | 在「节点管理」「日常运维」等页点操作，右侧抽屉由服务端规划：前置检查（✔ / ⚠ / ✖）、将执行的命令、执行步骤、需几级审批、窗口检查 | 任何一项「✖ 阻断」都会禁用「提交变更」，先处理阻断项 |
| 2. 选执行时间 | 「审批通过后立即执行」或「定时执行…」；「推荐时间」按窗口规则打分，点一下回填 | 勾选「紧急变更」可进入冻结期 / 禁止窗口，但审批更严、事后必须复盘 |
| 3. 提交 | 服务端再次规划并落库，变更编号 `CHG-xxxx`；高风险生产变更要输入动态验证码 | 写操作开关未开启 / 强制只读 / 版本不受支持时无法提交 |
| 4. 审批 | 状态「待审批」；有审批权限的人点「批准 / 驳回」；级数满足后进入下一步 | 审批有效期 24 小时，过期自动作废 |
| 5. 定时 | 选了「定时执行」且审批通过的变更状态为「已排期」，到点自动开始 | 窗口规则与冻结期**只在提交时检查**，之后新增冻结期不会自动拦截已排期变更，排期页会标红提示 |
| 6. 排队 | 「排队中」：审批通过、等待执行。**同一个集群内串行**，同一时刻只执行一个变更；不同集群互不排队 | 同一实例上已有未结束的变更时，新的会被前置检查拦截 |
| 7. 执行 | 「执行中」，按步骤逐条经执行器运行命令，实时显示步骤与日志 | 执行开始前会再次检查写操作开关；执行中关闭开关**不会**中断它 |
| 8. 手工确认步骤 | 某些步骤（如从负载均衡摘除 TiDB）显示「待人工确认」，要你在外部完成后点「我已完成，继续」 | 平台不替你做，也不检查你是否做了；最长等 12 小时，超时变更失败 |
| 9. 终态 | 成功 / 失败 / 已中止 / 已驳回 / 已取消 / 已过期 | 紧急变更在终态后要由申请人填写「事后复盘」 |

### 7.2 风险等级 × 环境 → 审批级别

每个变更先由服务端规划出**风险等级**，再按下表（默认策略，管理员可经双人复核修改）决定需要几级审批：

| 风险 | 测试 | 预发 | 生产 |
|---|---|---|---|
| 低 | 免审批 | 免审批 | 免审批 |
| 中 | 免审批 | 1 级 | 1 级 |
| 高 | 1 级 | 2 级 | 2 级，并且申请人需 MFA |

- 紧急变更（冻结期 / 禁止窗口内强行执行）规则固定：预发 / 生产**至少 2 级**审批；测试环境没有紧急通道。
- 「需 MFA」指**申请人**提交变更时要输入自己的动态验证码；审批人不需要。没绑定 MFA 的人提交高风险变更会被拒绝，请先到「我的账号」绑定。
- 免审批的变更提交后立即执行（选了定时则到点执行），但同样留痕。

各类变更的默认风险：

| 变更 | 风险 | 备注 |
|---|---|---|
| 启动实例 / 恢复 Leader 调度 | 低 | |
| 重启实例 / 驱逐 TiKV Leader | 中 | TiKV 先驱逐 Leader，重启后恢复调度 |
| 停止实例 | 高 | |
| 扩容 | 中 | |
| 缩容 | 高 | |
| 配置变更 | 中 | 含高危参数（目前仅 `replication.max-replicas`）时标高风险，同时会被前置检查直接拦截 |
| 主机维护：进入 / 结束 / 延长窗口 | 高 / 中 / 低 | |
| 按角色滚动重启 | 中 | |
| 滚动升级 | 高 | |
| 备份：全量 / 启动日志备份 | 中 | |
| 备份：停止日志备份（PITR） | 高 | 停止后无法恢复到停止之后的任意时间点 |
| 从备份恢复 | 高 | |
| 告警静默 | 低 | 不走审批，但受写操作开关约束并写审计 |

### 7.3 变更窗口、冻结期与推荐时间

| 概念 | 在哪里配置 | 作用 |
|---|---|---|
| 变更窗口规则 | 环境与设置 → 变更窗口规则（需「修改平台设置」） | 按「星期 + 时间段（可跨午夜）+ 风险 + 变更类型」划分：**禁止**（拒绝创建，紧急变更除外并留痕）/ **不建议**（给警告）/ **推荐**。时间按服务器本地时区 |
| 默认规则 | 未自定义时生效 | 备份窗口 01:30–04:00 不建议；工作日 09:00–12:00 与 14:00–18:00 业务高峰不建议；每日 22:00–06:00 夜间低峰推荐 |
| 冻结期 | 变更排期 → 变更冻结期 | 冻结期内**非紧急**变更在提交时被拒绝；确需执行请走紧急变更 |
| 推荐时间 | 提交抽屉的「推荐时间」 | 在未来 7 天内找出：避开冻结期、不命中禁止窗口、不与已排期变更在同一资源上重叠、得分最高的时段 |

窗口规则、冻结期、通知渠道、写操作开关都是**每个集群各自一份**，改之前先确认顶栏当前集群。

### 7.4 写操作的三道总闸

**任一道不满足，就不能提交也不能开始执行变更**：

| 总闸 | 说明 | 怎么解除 |
|---|---|---|
| READONLY 熔断文件 | 中控机上存在 `/etc/tidb-ops/READONLY` 时强制只读，**对所有集群同时生效**；提示「平台处于强制只读（存在 …）」 | 在中控机上删除该文件（由运维人员操作） |
| 写操作开关（每个集群各自一个） | 默认**关闭**（新接入的集群也是）。开启要**两名不同的管理员**先后确认（1 小时内有效）；**关闭只要一名管理员，立即生效**（熔断） | 先切换到目标集群，再到「权限与审计 → 写操作开关」操作 |
| 版本支持矩阵 | 集群版本不在 v7.5 / v8.1 / v8.5 系列时写操作自动降级为只读 | 升级到受支持版本 |

此外还需要已配置的执行器，否则提示「未配置执行器，无法执行变更」；手工接入的远程集群恒为只读。「写操作开关」页的「当前不能写的原因」那一行会写明还差哪个条件。

**开启写开关的步骤**（管理员）：管理员 A 在顶栏选好目标集群 → 「权限与审计 → 写操作开关」→ 核对卡片标题里的集群与环境 → 点「提议开启写操作」；管理员 B **1 小时内**用自己的账号登录，切换到**同一个集群**，进同一标签页，点「确认开启写操作」。必须是两个**不同**的账号，同一个人换浏览器不行。

> ⚠️ 开启写开关后，有权限的账号提交的变更会真正作用于集群。关闭开关只阻止**新的**提交与新变更的开始，已经在执行中的变更不会被中断。

### 7.5 中止、回滚与失败

- **取消**：只能取消尚未开始的变更（待审批 / 排队中 / 已排期），申请人或内置 DBA 可操作。
- **中止**：只能中止「执行中」且计划标记为可中止的变更（单实例停止 / 重启、缩容、进入主机维护），申请人或内置 DBA 可操作；缩容一旦进入 `tiup scale-in` 这类「不可中止」的步骤就不能再中止。扩容、配置变更、滚动重启、升级、备份、恢复本身不支持中止，只能等它结束。
- **回滚**：平台**没有「回滚」按钮**。失败或被中止时，引擎会按计划**尽力执行恢复命令**（如移除 evict-leader 调度、恢复 store limit、用变更前的拓扑还原配置），单条恢复失败会被忽略并记日志；滚动重启、升级、备份、恢复没有恢复命令，失败后需人工处理。
- 平台在执行中重启，该变更会被标记为「失败（被中断）」并提示「请核对集群状态后重新规划」，不会自动续跑，请到集群里核对真实状态。

> ⚠️ 「尽力恢复」不保证集群回到变更前状态。TiKV 重启 / 停止 / 缩容失败后务必到「节点管理」与「热点与调度」核对 evict-leader 调度、Store 状态是否已恢复。

## 8. 常见问题

### 登录与账号

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「用户名或口令错误」，但确定是对的 | 账号被禁用、用户名不对，或登错了平台（不同地址是各自独立的账号库） | 核对平台地址；请管理员确认账号状态 |
| 提示被锁定 | 连续输错 5 次 | 等 10 分钟，或请管理员在「用户管理」解锁（IP 维度的锁定只能等） |
| 登录后一直被踢回登录页 | 时钟不准 / 会话过期 / 平台重启 | 重新登录；仍然如此请联系运维检查服务器时间 |
| 忘记口令 / 动态验证码用不了 | — | 见 2.3 |

### 提交被拒绝 / 按钮点不了

| 提示或现象 | 含义 | 怎么办 |
|---|---|---|
| 按钮置灰，悬停提示「权限不足」 | 你的角色没有该能力（按钮保持可点，点了会在旁边提示） | 到「权限与审计 → 我的账号」看自己当前环境下的能力；需要权限找管理员 |
| 写操作开关未开启：由两名管理员确认后才能对该环境执行变更 | 该集群的开关没开 | 请两名管理员依次开启（7.4） |
| 平台处于强制只读 | 中控机上有 READONLY 文件 | 联系运维人员 |
| 该集群是手工接入的远程集群：平台只读 | 手工添加的集群恒只读 | 请管理员删除后用「从本机 tiup 导入」 |
| 集群版本不在平台支持范围内，写操作已降级为只读 | 版本不在 v7.5 / v8.1 / v8.5 | 升级集群到受支持版本，或接受只读 |
| 前置检查「✖ 阻断」 | 例如目标实例上已有未结束的变更、缩容后副本数不足 | 展开看阻断原因，处理后重新预览 |
| 计划时间落在变更冻结期内 | 冻结期内只允许紧急变更 | 换时间，或走紧急变更（审批更严、事后复盘） |
| 高风险变更要求 MFA | 生产高风险变更需要申请人二次确认 | 到「我的账号」绑定动态验证码 |
| 请求过于频繁 | 每个用户写类请求每分钟 60 次 | 稍等再试 |

### 审批与变更

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 审批人点不了「批准」 | 申请人不能审批自己的变更；同一人不能重复审批；管理员不能审批；审批级数未到 | 换另一名有审批能力的人 |
| 变更一直「待审批」 | 没人批，或审批有效期（24 小时）已过会自动作废 | 通知审批人；作废后重新提交 |
| 变更一直「排队中」 | 同一集群串行，前面有变更在执行 | 到任务中心看正在执行的变更 |
| 变更卡在「待人工确认」 | 有需要你在外部完成的步骤（如摘除负载均衡） | 完成后点「我已完成，继续」；最长等 12 小时 |
| 变更失败 / 被中断 | 命令失败或平台重启 | 看变更详情的步骤与日志；到集群里核对真实状态（7.5），再决定是否重新提交 |
| 想「回滚」已完成的变更 | 平台没有一键回滚 | 重新规划一个反向变更，或由 DBA 手工处理 |

### 数据与页面

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面数据为空 / 大量「数据缺失」 | Prometheus 或只读 SQL 账号没填 / 不通 | 展开「N 项数据缺失」看原因，联系管理员（《运维部署手册》5.10） |
| 总览 QPS 显示「—」 | 平台算出来是 0 | 见 6.1 |
| 慢 SQL 列表为空 | 你没有「查看慢 SQL」能力；或只读 SQL 账号没配；或最近没有超过阈值的慢查询 | 看自己的角色；联系管理员 |
| 页面提示「尚未接入集群」 | 还没接入，或你在所有集群的环境里都没有角色 | 联系管理员接入或授权 |
| 提示「当前集群已不可用，已切换到默认集群」 | 你正在用的集群被删除，或你在它的环境里的角色被拿掉 | 联系管理员 |
| 顶部横幅写着「写操作仍是原型模拟」 | 那是数据来源横幅的固定文案，运维模式的写操作是真实走变更引擎的 | 以「写操作开关」页的「执行器」一行为准（`sim` 才是模拟） |
| 通知没收到 | 渠道未配置 / 主机不在允许列表 / 被去重限流 | 管理员在「环境与设置 → 通知渠道」点「发送测试」，看「最近投递记录」 |

### 使用习惯建议

- 动手前先看顶栏：当前集群、环境标签、写开关状态。
- 生产变更先在测试 / 预发走一遍；高风险变更选业务低峰（推荐时间）。
- 复制命令只复制不执行；真正的变更一律走「预览 → 提交 → 审批」。
- 导出的巡检报告、审计日志按公司规定保管；不要截屏外传含业务数据的页面（管理员可能开启了水印）。

## 9. 术语表

| 术语 | 含义 |
|---|---|
| TiDB | 无状态 SQL 层，接收业务连接，可水平扩展 |
| PD（Placement Driver） | 集群大脑：保存元数据、分配时间戳（TSO）、调度 Region；多数派存活才可用，建议奇数个 |
| TiKV | 分布式事务型存储，数据按 Region 分片、多副本（默认 3） |
| TiFlash | 列存副本，加速分析查询 |
| TiCDC | 变更数据同步组件，把增量同步到下游 |
| Region | 数据分片单位，每个 Region 的多个副本组成一个 Raft 组 |
| Leader / Peer | Raft 组里负责读写的副本叫 Leader，其余叫 Follower / Peer |
| Store | PD 视角下的一个 TiKV / TiFlash 节点；状态 Up / Offline / Tombstone |
| evict-leader | 用 PD 的 evict-leader-scheduler 把某 Store 上的 Leader 迁走，重启前后用；恢复调度即移除该调度 |
| tiup | TiDB 官方部署与运维工具；平台的执行器最终调用 `tiup cluster …` |
| scale-out / scale-in | 扩容 / 缩容；TiKV 缩容后 Store 先进入 Offline，Region 迁完才变 Tombstone，再 `prune` 清理 |
| reload | 让修改后的配置通过滚动重启生效 |
| max-store-down-time | PD 判定 Store 宕机并开始补副本的时限（默认 30 分钟）；主机维护要在此之前结束 |
| store limit | 限制 Region 迁入 / 迁出速度，扩容时可调以控制均衡对业务的影响 |
| PITR / BR | 基于日志备份的任意时间点恢复 / 备份恢复工具 |
| DB Time | 数据库在 SQL 上花费的总时间，按 SQL 类型或阶段分解可看出时间花在哪 |
| 热点 | 读写集中在少数 Region / Store 的现象 |
| TOTP / MFA | 基于时间的一次性口令 / 多因素认证；本平台只在提交高风险变更时用于申请人二次确认，不用于登录 |
| 环境（测试 / 预发 / 生产） | 每个集群的属性：决定你在该集群里有什么角色、适用审批策略的哪一列；没有该环境角色的人看不到这个集群 |
| 当前集群 | 顶栏集群下拉里选中的集群；页面上的数据、变更、环境、角色、写开关都是它的 |
| 写操作开关 | 每个集群各自的总闸，开启需要两名不同管理员确认，关闭一名即可 |
| 熔断 / READONLY | 中控机上的 `/etc/tidb-ops/READONLY` 文件，存在即对所有集群强制只读 |
| 本机 tiup 集群 / 远程集群 | 「导入」产生可运维的本机 tiup 集群；「手工接入」产生只读的远程集群 |
| 变更（CHG-xxxx） | 平台里一次写操作的完整记录，编号贯穿审批、执行、审计；每个集群各自编号，会重复 |
| 双人复核 | 授予管理员、修改审批策略等高风险操作，要另一名管理员确认后才生效 |
| 自定义角色 | 管理员新建的一组能力，与内置 7 个角色并列 |
| 回放（replay） | 用一份已采集的样例数据包驱动页面，不连接任何集群 |
