# 变更排期

> 💡 查看、审批、取消「定时执行」的变更，并管理变更冻结期；变更窗口规则会在这里的周视图上着色。运维模式下所有登录用户都能看，审批需要「审批人」角色，冻结期增删需要「修改平台设置」权限（默认只有管理员）。回放 / 只读模式下这个页面只是原型演示，不连接任何真实变更。

> ⚠️ 平台从未在真实集群上执行过变更，本篇描述的行为来自代码与模拟执行器（sim）下的测试，一切以真实集群联调结果为准。首次在生产使用前，请先在测试环境走一遍「提交 → 审批 → 到点执行 → 查看结果」。

> 💡 **多集群**：平台可以纳管多个集群（见 [集群接入帮助](help:clusters)）。本页显示的变更、审批队列、冻结期都是**顶栏当前集群**的，周视图卡片标题里写着「集群 显示名」。审批人批准变更前，先确认顶栏集群与变更详情里的集群 / 环境；在别的集群提交的变更不会出现在这里。

## 这个页面做什么

- 把当前集群里所有选择了「定时执行」的变更按时间摆在一张周视图上，让你一眼看出什么时候、哪些变更会动哪些实例。
- 集中处理待审批的变更（通过 / 驳回），并在详情里看审批进度、前置检查、将执行的命令、执行步骤和日志。
- 管理**变更冻结期**（大促、春节等不允许变更的时间段）。
- 用颜色展示**变更窗口规则**（备份窗口、业务高峰、夜间低峰等），帮助挑选执行时间。
- 本页**不能直接新建变更**：排期是在各操作的「提交变更」面板里把「执行时间」选为「定时执行…」产生的。

两种模式的差异：

| 项目 | 运维模式（后端加了 --data-dir） | 回放 / 只读模式或纯静态打开 |
|---|---|---|
| 数据来源 | 后端变更引擎里的真实变更记录，每 2 到 8 秒刷新 | 写死在前端里的 6 条示例排期（S0001 到 S0006），刷新浏览器即还原 |
| 视图 | 排期表 + 周视图（可切换）+ 待审批队列 + 冻结期管理 | 月日历 / 列表两种视图、24 小时时间线 |
| 审批 | 真实用户登录、角色权限、职责分离、写入审计 | 右上角「当前身份」下拉框切换演示身份，点按钮即通过 |
| 到点执行 | 后端调度循环每 2 秒检查，到点自动开始 | 页面里每秒检查的演示定时器，可「快进到下一个排期」 |
| 执行器 | sim（模拟，不动任何集群）/ direct / sudo（真实执行 tiup 等命令） | 永远是原型模拟任务，不会作用于集群 |

> 💡 只读 / 回放模式的顶部横幅会写明「写操作仍是原型模拟」。看到 S0001 之类的编号、「⏩ 快进到下一个排期」按钮，说明你看到的是演示数据，请不要把它当成真实排期。

## 先搞清几个概念

| 名称 | 一句话解释 |
|---|---|
| 变更 | 一次要对集群或平台做的受控操作（重启、升级、扩缩容、配置修改、备份、恢复、主机维护等），编号形如 CHG-0001 |
| 定时执行 | 提交时指定一个将来的执行时间，审批通过后到点自动开始；与之对应的是「审批通过后立即执行」 |
| 审批级数 | 一个变更需要几个不同的审批人依次点「通过」，由「风险 × 环境」决定，默认值见下文「审批相关规则」 |
| 紧急变更 | 提交时勾选的特殊通道：可以落在冻结期或禁止窗口，但审批更严、事后要复盘 |
| 变更窗口规则 | 管理员配置的「哪些时段推荐 / 不建议 / 禁止做变更」，提交时检查一次，提示或拦截 |
| 变更冻结期 | 管理员配置的一段绝对时间（如大促期），非紧急变更不能在其中创建 |
| 写操作开关 | **每个集群各自一个**的总开关，关闭时该集群所有写操作（含提交变更）都被拒绝，开启需要两名管理员确认，见「[权限与审计](go:security)」 |
| 当前集群 | 顶栏集群下拉里选中的集群。**本页的排期表、周视图、待审批队列、冻结期、任务中心都只属于当前集群**；变更编号 `CHG-0001` 各集群各自编号，会重复 |

## 怎么用（按步骤）

### 一、申请人：提交一个定时变更

**前置条件**

- 你的角色拥有对应操作的能力：滚动重启 / 实例操作需要「单实例操作」（值班 SRE、DBA），升级、扩缩容需要「扩缩容 / 升级」（DBA），备份 / 恢复需要「备份恢复操作」（DBA）。没有能力时提交面板打不开，并提示「没有权限：xxx」。
- 「写操作开关」已开启，没有 READONLY 熔断文件，集群版本是 v7.5 / v8.1 / v8.5 系列。否则提交面板顶部出现黄色「当前不能提交：…」，提交按钮不可用。
- 你知道想在什么时间执行，以及该变更的预计耗时（面板会给出「预计 N 分钟」）。

**步骤**（以「晚上低峰滚动重启 TiKV」为例，申请人 alice，生产环境）

1. 打开「[日常运维](go:ops)」→「集群操作」标签页，「操作类型」选「滚动重启 restart」，「角色」选 `tikv`，点「预览并提交变更」。其他入口：「[节点管理](go:nodes)」里各向导最后一步的「提交扩容申请…」「提交缩容申请…」「提交变更申请…」「提交维护申请…」，效果相同。你会看到右侧滑出一个以变更标题命名的提交面板，先显示「正在由服务端规划并检查…」，随后给出内容。
2. 看面板顶部一行标签：风险（如「中风险」）、**「集群 X」（悬停提示「本变更将提交到此集群」，X 是顶栏当前集群的显示名）**、「prod 环境需 1 级审批」、「预计 N 分钟」。**提交前先确认「集群 X」就是你要动的集群**；不对就关闭面板、切换集群再来。这里的级数就是该变更需要几个不同的审批人（按该集群的环境取审批策略）。
3. 看「前置检查（服务端）」。红色 ✖ 表示阻断项，面板底部按钮会变成灰色「存在阻断项」，必须先处理（例如实例不健康、主机正在维护）才能提交；橙色 ⚠ 只是提醒；绿色 ✔ 表示通过。
4. 看「窗口检查」。它列出命中的窗口规则：红色「落在禁止变更窗口…」、橙色「落在不建议变更的窗口…」、绿色「落在推荐窗口…」；没有命中则显示「未命中任何窗口规则」。标题旁灰字说明按哪个时间评估（此时是「按当前时间（审批通过后立即执行）」）。
5. 看「将执行的命令」和「执行步骤」。步骤旁的「不可中止」标签表示一旦开始就不能中止；「需人工确认」表示执行到这一步会停下来等你确认。
6. 「变更说明 / 工单号」填工单号或原因，例如 `OPS-1234 内核补丁`，审批人会看到。
7. 「执行时间」下拉框选「定时执行…」。下方出现一个时间输入框，默认值是「服务器当前时间加 1 小时」所在的整点（例如现在 10:40，默认 11:00）；同时「推荐时间」一行列出最多 5 个按钮，形如「10-07 22:00 · 评分 70」。点评分最高的按钮会自动回填时间，也可以手工改时间输入框。每次改动后约 0.4 秒，「窗口检查」会按新时间重新评估，标题旁变成「按计划时间 2026-10-07 22:00」。理想结果是出现绿色「落在推荐窗口「夜间低峰」…」。
8. 需要走紧急通道时才勾选「紧急变更（可进入冻结期，审批更严，事后必须复盘）」。勾选后窗口检查会重新评估：原本红色的「禁止」会变成橙色「按紧急变更处理，需留痕并事后复盘」，提交按钮恢复可用。
9. 高风险且环境策略要求 MFA（默认生产高风险）时，面板会多出「申请人动态验证码（MFA）」，填你验证器里的 6 位数字。没有绑定过 MFA 时先到「[权限与审计](go:security)」绑定。
10. 点「提交变更」。成功时右上角提示：需要审批为「变更 CHG-0001 已提交，等待审批」；免审批且定时为「变更 CHG-0001 已排期」；免审批且立即执行为「变更 CHG-0001 已开始执行」。随后页面自动跳到「节点管理 → 任务中心」并展开该变更。

**提交失败时面板底部红字会写原因**

| 红字 | 含义与处理 |
|---|---|
| 计划时间落在变更冻结期「X」内；确需执行请走紧急变更 | 命中冻结期。改期，或勾选「紧急变更」再提交 |
| 窗口规则拦截：落在禁止变更窗口… | 命中 block 规则且非紧急。改期，或勾选「紧急变更」 |
| 与已排期的变更 CHG-xxxx 在时间与资源上冲突 | 同一实例或主机在重叠时间已有排期。改时间，或先取消那一个 |
| 计划执行时间已过 | 选的时间早于服务器当前时间 1 分钟以上。重新选时间 |
| 高风险变更需要申请人二次验证（MFA） | 没填验证码，或尚未绑定 MFA（此时红字后会追加绑定提示） |
| 动态验证码错误或已被使用 | 等下一个验证码再填，每个验证码只能用一次 |

**后果与撤销**：提交只创建变更记录，不会动集群。需要审批时进入「待审批」，免审批时直接进入「已排期」（定时）或开始执行（立即）。提交后可以随时在审批完成前、执行开始前取消（见下文「四、取消、中止与复盘」），审计日志会记录创建动作。

### 二、审批人：通过或驳回

**前置条件**：你的角色是「审批人」（同时拥有审批中风险、审批高风险能力）；你不是该变更的申请人；你没有审批过该变更。DBA、SRE、管理员都不能审批。

**步骤**

1. 打开「变更排期」。侧栏「变更排期」旁的橙色数字角标就是待审批数量；也可以在「节点管理 → 任务中心」顶部看到「待你审批（N）」区域。
2. 在页面下方「待审批队列」找到变更（定时变更也可以在「排期表」里用状态筛选「待审批」查看，行内有「审批」按钮，作用是打开详情），看「内容」下的灰字：「计划 2026-10-07 22:00」或「审批后立即执行」，有「紧急」标签说明是紧急变更；「审批」列显示「已通过级数/需要级数」。
3. 点这一行的「详情」（排期表里点整行）打开抽屉。抽屉里逐项核对：申请人与「工单 / 说明」是否对得上；「计划执行」与预计耗时；红 / 橙色提示（与其他变更冲突、落在冻结期）；「前置检查（创建时）」；「将执行的命令」；「执行步骤」里标了「不可中止」的步骤；「参数」。
4. 同意：在「审批意见 / 驳回原因（驳回必填）」框里可选填意见，点抽屉底部的「通过」。列表里的「审批」按钮**不会直接通过**，只是打开这个详情，核对完再点这里的「通过」才提交。右上角提示「已通过 CHG-0001」。审批进度加 1；达到所需级数后：定时变更状态变为「已排期」，周视图出现色块；不定时变更变为「排队中」并马上开始执行。需要多级审批时，还要由另一位不同的审批人再点「通过」，期间状态仍是「待审批」。
5. 不同意：在同一个框里**必须**填写原因，点「驳回」。没有填写会提示「驳回必须填写原因」。成功后提示「已驳回 CHG-0001」，变更终止为「已驳回」，申请人需要重新提交。驳回没有二次确认。

**通过 / 驳回按钮是灰色或看不到时**，悬停灰色按钮看原因：该变更不在待审批状态、你是申请人（申请人要撤回请用「取消变更」）、你已审批过、你没有该风险等级的审批权限。

**后果与撤销**：一次「通过」登记后**不能撤销**；驳回后不能恢复，只能重新提交。审批动作写入审计日志。

> ⚠️ 看清「计划」时间。定时变更如果直到计划时间之后才被批准，引擎会立刻把它置为「排队中」并执行，而不是等下一个窗口，此时不会再检查窗口规则或冻结期。已过点的变更宁可驳回让申请人重提。

**审批相关规则（代码强制）**

- 只有「审批人」角色同时拥有「审批中风险」「审批高风险」能力。
- 申请人不能审批或驳回自己的变更；同一个人不能对同一变更重复审批；多级审批需要不同的人。
- 审批级数由「风险 × 环境」决定，默认值：低风险任何环境免审批；中风险测试环境免审批、预发和生产 1 级；高风险测试 1 级、预发和生产 2 级，生产高风险另要求申请人 MFA。紧急变更在预发 / 生产至少 2 级，测试环境没有紧急通道、按常规。策略可在「权限与审计」里经双人复核修改，且有写死的下限（生产高风险至少 2 级 + MFA、生产中风险至少 1 级、预发高风险至少 2 级）。
- 审批有效期默认 24 小时（定时变更的计划时间更晚时，有效期延长到计划时间）。到期仍未审批完成，变更变为「已过期」，不能恢复。

### 三、到点之后：执行与完成

这一段由系统自动推进，申请人或 DBA 只需要盯着结果。

1. 后端每 2 秒检查一次。到达计划时间，「已排期」变为「排队中」，轮到执行时变为「执行中」。
2. 执行前总闸再检查一次：若这时「写操作开关」已关闭、存在 READONLY 熔断文件或集群版本不在支持范围，变更**不会等待**，直接变为「失败」，原因是「执行前检查未通过」。
3. 打开「节点管理 → 任务中心」（或在变更详情点「在任务中心查看」），找到该变更。你会看到进度条和步骤清单，步骤图标含义：✔ 完成、◔ 进行中、○ 等待、⏸ 待人工确认、✖ 失败、↷ 跳过。
4. 有步骤停在 ⏸「待人工确认」时（例如开启「集群前有负载均衡」后缩容 / 维护 TiDB 节点要求先摘除负载均衡），申请人或 DBA 按步骤下方的橙色说明手工完成后，点该步骤的「我已完成，继续」。其他人看到的是「等待申请人 / DBA 确认」。
5. 全部步骤完成后状态为「成功」。失败时展开详情看「失败原因」与日志，**人工核对集群状态**后重新规划，平台不会自动重试。
6. 紧急变更结束后申请人需要补复盘，见下一节。

**去哪里看结果**：「节点管理 → 任务中心」（筛选芯片：全部 / 待审批 / 排队 / 执行中 / 已结束）、本页周视图（颜色按状态）、「[日常运维](go:ops)」→「变更审计」标签页（最近 30 条）、「[权限与审计](go:security)」里的审计日志（每条执行的命令）。变更创建、审批、驳回、开始、成功、失败等事件也会按「[环境与设置](go:settings)」里配置的通知渠道推送。

### 四、取消、中止与复盘

**取消（尚未开始执行：待审批 / 排队中 / 已排期）**，申请人或 DBA 可操作：

1. 在本页打开变更详情，点「取消变更」；弹出确认抽屉「取消变更」，点「确认取消」。提示「已取消 CHG-0001」，状态变为「已取消」，占用的实例被释放。这里不会让你填原因，记录为「用户取消」。
2. 或在「任务中心」该变更行点「取消」，打开「取消变更」抽屉，可选填「取消原因」，点「确认取消」。

取消**不可恢复**，需要时重新提交。

**中止（执行中）**，申请人或 DBA 可操作，只在任务中心：

1. 展开执行中的变更，点「中止」；抽屉「中止执行」说明「会停止后续步骤，并尽力执行计划里的回滚命令；已越过不可逆步骤的变更无法中止」，点「确认中止」，提示「已发出中止指令」。
2. 只有「可中止」的计划才有「中止」按钮（单实例重启 / 停止、缩容、进入主机维护）；滚动重启、滚动升级、备份、恢复没有该按钮。

**事后复盘（紧急变更）**，仅申请人：

1. 变更结束（成功 / 失败 / 已中止）后，任务中心该变更行出现橙色「待复盘」标签和「填写复盘」按钮。
2. 点「填写复盘」，在「复盘内容（必填）」里写为什么紧急、做了什么、有无遗留风险与改进项，点「提交复盘」，提示「复盘已保存 CHG-0001」，「待复盘」标签消失；之后按钮变成「修改复盘」。

### 五、管理员：配置变更窗口规则

窗口规则在「[环境与设置](go:settings)」页面下方的「变更窗口规则」卡片里维护（在「通知渠道」卡片之后、「关于与升级」卡片之前）。

**前置条件**：你拥有「修改平台设置」权限（内置管理员角色）。没有时卡片顶部显示「你没有「修改平台设置」（settings.edit）权限，窗口规则为只读」，按钮不出现。

**新增一条规则**

1. 打开「环境与设置」，向下滚动到「变更窗口规则」卡片，点右上角「＋ 新增规则」。右侧滑出「新增窗口规则」抽屉，默认值：开始 22:00、结束 06:00、模式「不建议」、启用。
2. 逐项填写（含义见下文「窗口规则字段」）：名称、星期、开始、结束、模式、适用风险、限定变更类型（点开折叠区）、备注。
3. 勾选「启用该规则」，点「保存」。成功时抽屉关闭，提示「规则已添加」，规则出现在表格里，卡片标题旁的计数加 1，并显示「已自定义」。
4. 填写有误时抽屉里红字提示，例如「请填写规则名称」「开始时间格式应为 HH:MM（00:00–23:59）」「开始与结束时间不能相同（全天请用 00:00–24:00）」；服务端校验失败会显示「窗口规则不合法：第 N 条规则：…」。

**编辑 / 停用 / 删除 / 恢复默认**

- 编辑：点该行「编辑」，改完点「保存」，提示「规则已更新」。
- 停用 / 启用：直接勾选该行「启用」复选框，提示「规则已停用」或「规则已启用」；停用的规则不参与检查和着色，行显示为灰色。
- 删除：点「删除」，在确认抽屉点「确认删除」，提示「规则已删除」。**不可恢复**。
- 恢复默认：点「恢复默认」，确认抽屉点「恢复默认」，提示「已恢复默认规则」，**当前全部自定义规则都会丢失**。

**所有改动保存后立即生效**，写入审计，并同步到「变更排期」的周视图着色。已经提交的变更不会被重新检查。

**示例 1：周五 18:00 之后禁止高风险变更（含整个周末）**

「周五 18:00 之后」要拆成三条规则，因为一条规则只能在一天的起点算星期：

| 字段 | 规则 A | 规则 B | 规则 C |
|---|---|---|---|
| 名称 | 周五晚禁止高风险变更 | 周末禁止高风险变更 | 周一早禁止高风险变更 |
| 星期 | 周五 | 周六、周日 | 周一 |
| 开始 / 结束 | 18:00 / 24:00 | 00:00 / 24:00 | 00:00 / 08:00 |
| 模式 | 禁止 | 禁止 | 禁止 |
| 适用风险 | 高风险 | 高风险 | 高风险 |
| 限定变更类型 | 不勾选 | 不勾选 | 不勾选 |
| 备注 | 周末无人值守 | 周末无人值守 | 周末无人值守 |

保存后你会看到：

- 「变更窗口规则」表格出现对应行，例如「周五 / 18:00–24:00 / 禁止 / 高」。
- 在「变更排期」翻到任意一周，周五 18:00 之后、周六周日整天、周一 00:00 到 08:00 出现红色斜纹带，带上写着规则名；鼠标悬停显示「周五晚禁止高风险变更（禁止，适用风险 高）」。
- 用「滚动升级」（高风险）提交面板验证：执行时间选周五 19:00，「窗口检查」出现红色「落在禁止变更窗口「周五晚禁止高风险变更」（周五 18:00–24:00）：计划 10-09 19:00 起约 N 分钟，非紧急变更不允许；请改期，确需执行请走紧急变更（周末无人值守）」，下面再有一条红色「窗口规则禁止（紧急变更除外）」，提交按钮变灰为「窗口规则禁止」。勾选「紧急变更」后红色变成橙色「…按紧急变更处理，需留痕并事后复盘」，按钮恢复。
- 同一时间换成「滚动重启」（中风险）则不命中，因为规则只适用高风险。
- 窗口按**相交**判断：周五 17:30 开始、预计 60 分钟的高风险变更，计划窗口延伸到 18:30，同样被拦。

**示例 2：白天禁止缩容（限定变更类型）**

| 字段 | 填写 |
|---|---|
| 名称 | 白天禁止缩容 |
| 星期 | 不勾选（每天） |
| 开始 / 结束 | 09:00 / 18:00 |
| 模式 | 禁止 |
| 适用风险 | 不勾选（全部风险） |
| 限定变更类型 | 点开折叠区，只勾「缩容」 |

保存后表格「适用风险 / 类型」列显示「全部」和灰字「缩容」。只有缩容变更在 09:00 到 18:00 的计划窗口被拦；同一时间的滚动重启、备份不受影响。注意周视图的红色斜纹**不区分变更类型**，会画在所有人的周视图上（见「已知限制」）。

**示例 3：夜间推荐做升级（推荐 + 跨午夜）**

| 字段 | 填写 |
|---|---|
| 名称 | 夜间升级窗口 |
| 星期 | 周二、周三、周四 |
| 开始 / 结束 | 22:00 / 06:00（结束小于开始表示跨午夜） |
| 模式 | 推荐 |
| 适用风险 | 高风险 |
| 限定变更类型 | 只勾「滚动升级」 |

保存后表格时间列旁出现「跨午夜」小标签。因为跨午夜规则按**起点所在日**判断星期，它覆盖周二 22:00 到周三 06:00、周三 22:00 到周四 06:00、周四 22:00 到周五 06:00，周二凌晨 00:00 到 06:00 不属于它。滚动升级提交面板里，执行时间选周三 23:00 会看到绿色「落在推荐窗口「夜间升级窗口」（周二至周四 22:00–06:00）」，推荐时间按钮的评分也会加分。

### 六、管理员：配置变更冻结期

冻结期在「变更排期」页面右下角的「变更冻结期」卡片里维护，**不在**「环境与设置」。**冻结期是每个集群各自一份**：它只对当前集群的变更生效；要给多个集群都冻结（如大促期），在每个集群下各加一次（先在顶栏切到对应集群）。

**前置条件**：「修改平台设置」权限。没有时卡片底部是灰字「增删冻结期需要「修改平台设置」（settings.edit）权限。」，没有输入框。

**新增冻结期**

1. 在「新增冻结期」区域填「名称」，例如 `春节保障期`；名称会显示在周视图斜纹、冲突提示和被拒绝的提示里。
2. 「开始」「结束」用日期时间选择器（精确到分钟，按你的浏览器本地时间输入，保存为绝对时刻）。示例：开始 `2027-02-05 00:00`，结束 `2027-02-14 00:00`。结束必须晚于开始。
3. 点「添加冻结期」。成功提示「冻结期已添加」，上方表格出现一行（名称 / 起 / 止 / 状态：未开始、进行中、已结束）。缺字段提示「请填写名称、开始与结束时间」，时间反了提示「结束时间必须晚于开始时间」。
4. 验证：在周视图翻到对应周，冻结时段出现红色斜纹带，写着冻结期名称，对应日期的表头出现红色「冻结」标签。

**删除**：点该行红色「删除」，立即生效，**没有二次确认**，提示「冻结期已删除」。

**冻结期的效果**

- 创建变更时，如果计划窗口（定时变更用计划时间，立即执行的用当前时间，长度取预计时长）与任一冻结期有任何重叠，且**没有勾选紧急变更**，后端直接拒绝，提示「计划时间落在变更冻结期「春节保障期」内；确需执行请走紧急变更」。
- 勾选「紧急变更」可以创建，但审批级数在预发 / 生产至少 2 级，并要求事后复盘。
- 推荐时间会自动避开冻结期。
- 冻结期与窗口规则不同：它没有「不建议 / 推荐」软档位，只有「非紧急一律拒绝」。

> ⚠️ 冻结期只在**创建变更时**检查。后加的冻结期不会取消已经排好的变更，已审批的定时变更到点仍会自动执行。新增冻结期后，请回到周视图查看是否出现橙色「落在冻结期」提示，并手工取消不该执行的变更（申请人或 DBA 才能取消）。

### 窗口规则字段

| 字段 | 含义 | 可选值 / 默认 | 影响 |
|---|---|---|---|
| 名称 | 规则名，最多 40 字 | 必填 | 显示在检查提示和周视图里 |
| 星期 | 规则适用的星期 | 不勾选或七天全选等于每天 | 不在所选星期内的日子，规则不起作用 |
| 开始 / 结束（HH:MM） | 规则时间段，按**服务器本地时区** | 开始 00:00 到 23:59；结束 00:00 到 24:00；开始与结束不能相同，全天写 00:00 到 24:00 | 结束早于开始表示跨午夜 |
| 模式 | 禁止（block）/ 不建议（avoid）/ 推荐（prefer） | 新增时默认「不建议」 | 决定检查结果与推荐打分，见下表 |
| 适用风险 | 低 / 中 / 高 | 不勾选 = 全部风险 | 只对勾选的风险等级的变更生效 |
| 限定变更类型 | 实例操作、扩容、缩容、配置变更、进入维护、结束维护、延长维护、备份、恢复、滚动重启、滚动升级 | 不勾选 = 全部类型 | 只对勾选的类型生效 |
| 备注 | 最多 200 字 | 可空 | 附在检查提示后面 |
| 启用 | 是否参与检查 | 默认启用 | 停用的规则不参与检查和着色 |

规则条数上限 50。一条规则命中的判断：规则展开后的时间段与变更计划窗口 [开始时间, 开始时间 + 预计时长) 有任何重叠。

| 模式 | 提交面板「窗口检查」 | 创建变更时 | 推荐时间打分 |
|---|---|---|---|
| 禁止 | 红色「落在禁止变更窗口」，提交按钮变灰「窗口规则禁止」 | 非紧急变更被拒绝（提示「窗口规则拦截」）；紧急变更放行，显示橙色提醒 | 该起点被排除 |
| 不建议 | 橙色「落在不建议变更的窗口」 | 允许，把提醒写进变更日志 | 每命中一条减 30 |
| 推荐 | 绿色「落在 / 部分落在推荐窗口」 | 允许 | 命中加 50，整个变更都落在窗口内再加 20 |

**优先级**：规则没有优先级字段，所有启用且适用的规则都会被评估，结果叠加；只要有一条禁止命中且非紧急，就被禁止。周视图着色按 推荐 → 不建议 → 禁止 的顺序绘制，禁止画在最上层。冻结期的限制强于窗口规则。

**默认规则**（没自定义过时使用，点「恢复默认」可还原）：

| 名称 | 星期 | 时间 | 模式 | 适用风险 |
|---|---|---|---|---|
| 备份窗口 | 每天 | 01:30 到 04:00 | 不建议 | 中 / 高 |
| 业务高峰 | 周一到周五 | 09:00 到 12:00 | 不建议 | 中 / 高 |
| 业务高峰 | 周一到周五 | 14:00 到 18:00 | 不建议 | 中 / 高 |
| 夜间低峰 | 每天 | 22:00 到 06:00 | 推荐 | 全部 |

> ⚠️ **默认规则里没有任何「禁止」**，默认配置下窗口规则只会提醒、不会拦截。需要真正禁止时请自己新增，例如上面的示例 1。把规则全部删除后，任何时间都不做窗口检查。

> ⚠️ 窗口规则只在**提交 / 预览时**检查一次，到点执行时不会复查。审批耗时过长导致实际执行时间偏离计划时，请自己核对。

### 推荐时间怎么算

提交面板里的「推荐时间」由后端计算（默认请求未来 7 天、最多 5 个结果，接口上限 14 天、10 个）：

1. 先按变更类型规划出计划，得到风险和预计时长；计划本身有阻断项（红色检查）时不推荐。
2. 起点从「现在 + 10 分钟」向上对齐到整 30 分钟，之后每 30 分钟一个候选。
3. 排除：落在冻结期的、命中禁止规则的、与已排期或执行中的变更在时间上重叠且涉及同一实例 / 主机的候选。
4. 打分：命中推荐窗口 +50，整个变更都在推荐窗口内再 +20；每命中一个不建议窗口 −30；每晚一天 −2。
5. 按分数从高到低排序，同一天内相隔不足 2 小时的只保留分高的一个。
6. 按钮上显示「月-日 时:分 · 评分 N」，悬停显示原因，例如「整个变更落在推荐窗口「夜间低峰」（每天 22:00–06:00）内」。

按默认规则举例：一次 60 分钟的中风险变更，从 22:00 到 00:30 之间、或 04:00 到 05:00 之间开始（整个落在夜间低峰、又不与备份窗口重叠）得分最高（70，再按晚的天数每天减 2）；从 01:00 开始会与备份窗口重叠，得分降到 40。低风险变更不受备份窗口和业务高峰影响（它们只适用中 / 高风险）。

> 💡 推荐只保证「不违反规则、不与已排期变更冲突」，不代表业务真的空闲，也不检查审批人是否在岗。

### 状态与状态机

```
待审批 pending ──审批达标──► 已排期 scheduled ──到点──► 排队中 approved ──轮到执行──► 执行中 running ──► 成功 succeeded
   │  │  │                      │                          │                              │  └─► 失败 failed
   │  │  └─驳回─► 已驳回 rejected                           └─取消─► 已取消 cancelled        └─► 已中止 aborted
   │  └─取消─► 已取消 cancelled                  （不定时的变更审批达标后直接进入 排队中）
   └─超时未审批─► 已过期 expired
```

| 状态 | 含义 | 谁能做什么 |
|---|---|---|
| 待审批 | 等待所需级数的审批 | 审批人：通过 / 驳回；申请人或 DBA：取消；超过审批有效期自动「已过期」 |
| 已排期 | 已批准且定时，等待到点 | 申请人或 DBA：取消；到点自动变「排队中」 |
| 排队中 | 已批准，等待执行：不定时变更刚批准、定时变更刚到点、前面有变更正在执行 | 申请人或 DBA：取消；轮到后自动开始 |
| 执行中 | 正在按步骤执行命令 | 申请人或 DBA：可中止的计划可中止；有「待人工确认」步骤时点「我已完成，继续」 |
| 成功 | 全部步骤完成 | 终态；紧急变更申请人补复盘 |
| 失败 | 某一步失败、执行前总闸检查未通过、或平台在执行中重启 | 终态，需人工核对集群状态后重新规划 |
| 已中止 | 被人工中止，并尽力执行了计划里的恢复命令 | 终态 |
| 已驳回 / 已取消 / 已过期 | 未执行就结束 | 终态，需要时重新提交 |

### 任务中心里的执行控制

「节点管理 → 任务中心」是执行阶段的主控台。注意按钮文字与本页不同：

| 按钮 | 出现条件 | 后果 |
|---|---|---|
| 批准 / 驳回 | 待审批，规则同本页的「通过 / 驳回」 | 「批准」没有意见框，提示「已批准 CHG-0001」；「驳回」弹出抽屉，必须填「驳回原因（必填）」，点「确认驳回」 |
| 取消 | 待审批 / 排队中 / 已排期，且你是申请人或 DBA | 抽屉里可选填取消原因，点「确认取消」 |
| 我已完成，继续 | 某一步处于「待人工确认」，且你是申请人或 DBA | 平台认为你已按提示手工完成并继续后续步骤。平台**无法验证**你是否真的摘除了节点 |
| 中止 | 执行中、计划可中止，且你是申请人或 DBA；已越过「不可逆」步骤后会被拒绝 | 停止后续步骤，并尽力按相反顺序执行计划里的恢复命令（如移除驱逐 Leader 调度、还原 PD 参数），单条恢复命令失败会被忽略 |
| 填写复盘 / 修改复盘 | 紧急变更已结束且你是申请人 | 保存复盘文字 |

**关于「回滚」**：

- 平台**没有**对已成功变更的一键回滚按钮。失败或被中止时，引擎会自动执行计划里预置的恢复命令：单实例重启 / 停止与驱逐 Leader（移除驱逐调度）、进入主机维护（还原 PD max-store-down-time、移除驱逐调度）、TiKV 缩容（移除驱逐调度）、TiKV 扩容（还原 store limit）、配置变更（用变更前的拓扑 edit-config）。
- 滚动重启、滚动升级、备份、恢复**没有**自动恢复命令。
- 配置变更成功后想改回旧值，在节点详情的变更历史里点「回滚到 X」，这只是生成一份把值改回去的**新变更草稿**，仍要走提交 → 审批 → 执行。

### 同一集群内串行与资源冲突

后端在**同一个集群内**同一时刻**只执行一个变更**，不管它们是否涉及同一实例；**不同集群之间互不串行、可以同时执行**（没有跨集群的全局互斥）：

- 多个变更同时到点时，只有一个进入「执行中」，其余保持「排队中」，等前一个结束再抢占执行，先后顺序不保证与计划时间严格一致。
- 排队中的变更不会超时，但如果前一个变更卡在「待人工确认」，它会占着执行名额最长 12 小时，后面的变更全部被堵住。看到长时间「排队中」时，先去任务中心看是否有变更在等人工确认。
- 排队也会让变更晚于计划时间开始，窗口规则不会因此重新检查。

创建定时变更时另有**资源冲突检查**：与已排期 / 执行中 / 定时待审批的变更时间窗口重叠，并且涉及同一个实例或同一台主机，后端拒绝创建，提示「与已排期的变更 CHG-xxxx 在时间与资源上冲突」。

> 💡 周视图的窗口底色按浏览器所在时区绘制，后端的窗口检查按服务器本地时区判断；两者不在同一时区时会错位，请以提交面板里的「窗口检查」文字为准。

## 执行后果与风险

| 事项 | 后果 | 能否撤销 |
|---|---|---|
| 到点自动执行 | 已批准的定时变更到点后**无人确认即自动执行**真实命令（执行器为 direct / sudo 时） | 只能在「待审批 / 排队中 / 已排期」阶段取消；执行中只能中止，且只有部分计划可中止 |
| 不可逆步骤 | 滚动重启、滚动升级、备份、恢复，以及配置变更的 reload 步骤、扩缩容的下线步骤标为「不可逆」，开始后无法中止；滚动升级和恢复没有自动恢复命令，失败只能人工处理 | 否 |
| 晚批准即执行 | 计划时间之后才批准的定时变更立即执行，不再检查窗口规则或冻结期 | 否，审批人应驳回 |
| 平台重启 | 升级、重启平台时，执行中的变更被标为「失败」，可能残留驱逐 Leader 调度等中间状态，需人工核对集群；「已排期」的变更不受影响，平台起来后到点或已过点的会立刻开始；「排队中」的变更不会被自动拉起，请到任务中心检查，必要时取消重提 | 视情况 |
| 模拟执行器 | 执行器为 sim 时，变更只在平台里走完流程，**不会改动任何集群**，状态「成功」不代表真实执行过。「权限与审计 → 部署自检」的「特权分离」一行会写明当前是模拟执行器、direct 还是 sudo | — |

窗口规则 / 冻结期的改动、审批、取消、执行的每个命令都会写入审计日志（哈希链），在「权限与审计」中查看。

## 常见问题与注意

- **为什么我的变更没有出现在周视图？** 周视图只显示「定时执行」的变更；立即执行的看任务中心。也检查是否翻到了正确的周、是否取消勾选了「显示已结束」。
- **「通过」按钮是灰的？** 悬停看原因，见「二、审批人」。
- **想改期怎么做？** 运维模式没有改期按钮：取消后重新提交（原型里有改期）。
- **已过期的变更能恢复吗？** 不能，需要重新提交。
- **想知道某个时间段为什么推荐 / 不推荐？** 鼠标悬停「推荐时间」按钮看原因；或到「环境与设置」查看窗口规则。
- **变更一直「排队中」？** **同一个集群**里前面有变更在执行或在等人工确认（别的集群的变更不会堵住它），见「同一集群内串行与资源冲突」。
- **管理员能验证窗口规则吗？** 管理员没有发起变更的能力，提交面板会提示没有权限。请让 DBA 或 SRE 打开对应提交面板、只看「窗口检查」，点「取消」关闭即可，不会创建变更。

## 已知限制与易混淆点

核对于代码，格式为「界面 / 文档写的是 A，实际是 B」。

| 界面 / 文档写的是 | 实际是 | 建议 |
|---|---|---|
| 默认的窗口规则「备份窗口」「业务高峰」听起来会拦截变更 | 默认 4 条规则里没有任何「禁止」，只有「不建议」和「推荐」，提交时仅出现橙色提醒 | 需要拦截时自行新增「禁止」规则（示例 1 到 2） |
| 提交面板的「窗口检查」看起来检查了所有限制 | 它只评估窗口规则，**不显示冻结期**；落在冻结期的非紧急变更要到点「提交变更」才被拒绝 | 提交前先在周视图确认目标时间没有冻结斜纹 |
| 新增冻结期会「冻结」所有变更 | 冻结期只在创建变更时检查；已审批的定时变更到点照常自动执行 | 新增后检查周视图的橙色「落在冻结期」提示，手工取消 |
| 「新建排期」按钮 | 不创建任何排期，只弹出引导抽屉 | 从各操作的提交面板选「定时执行…」 |
| 提交面板「紧急变更（…事后必须复盘）」，任务中心「复盘内容（必填）」 | 复盘只在你点「提交复盘」时才要求非空；平台不强制申请人去填，不填只是一直显示「待复盘」 | 值班约定复盘期限 |
| 页面提示「紧急变更需 2 级审批」 | 仅预发 / 生产如此；测试环境没有紧急通道，按常规级数 | 以提交面板顶部的「N 级审批」为准 |
| 周视图的窗口色带 | 画的是所有已启用规则：不区分「限定变更类型」，适用风险只在悬停提示里写；时区用浏览器的，检查用服务器的 | 以提交面板里的「窗口检查」文字为准 |
| 本页详情里的「通过」「取消变更」，提示「已通过」 | 任务中心里同一动作叫「批准」「取消」，提示「已批准」；本页取消不填原因，任务中心可填 | 两处效果相同，按所在页面的文字找按钮 |
| 变更详情抽屉像是变更的全部控制台 | 没有「中止」「确认执行」「回滚」，它们只在「节点管理 → 任务中心」 | 点「在任务中心查看」 |
| 「排队中」听起来会继续执行 | 平台重启后，处于「排队中」的变更不会被自动拉起 | 重启平台后检查任务中心，取消并重新提交 |
| 删除冻结期 / 窗口规则像是可以撤回 | 冻结期删除无确认、不可恢复；窗口规则删除有确认，但同样不可恢复 | 删除前截图或抄下字段 |
| 「排队中」「全局串行」像是跨所有集群 | 只在**同一个集群内**串行；不同集群的变更互不排队、可同时执行 | 两个集群同时做变更前，自己安排好先后与人手 |
| 变更编号 `CHG-0001` 在平台里唯一 | 每个集群各自编号，会重复；通知消息、审计日志里同样如此 | 区分集群看审计日志的「集群」列（tiup 集群名）或通知里的「集群：」 |
| 冻结期 / 窗口规则配一次就覆盖所有集群 | 每个集群各自一份 | 逐个集群配置（先在顶栏切换） |
| 通知里的「查看」链接会直接打开那个集群的排期页 | 非主集群的链接带 `?cluster=<id>`；登录后页面读取它并切换到该集群，但**只有该集群对你可见时才生效**，否则静默忽略 | 点开后先看顶栏集群与环境标签；不是目标集群就联系管理员补权限 |
| 周视图 / 排期表 / 待审批队列里能看到所有集群的变更 | 只有当前集群的；其他集群的待审批变更要切过去才能看到（审批人需要在对应环境有审批能力） | 值班审批人轮流切换各集群看一遍 |

> 💡 回放 / 只读模式的演示排期编号（S0001 起）、演示窗口规则与运维模式无关，不要拿来推断真实行为。
