# 快速入门

> 💡 面向值班运维人员的上手指南：平台是什么、当前处于哪种模式、怎么登录、各角色能做什么（含自定义角色）、一次变更怎么走完。适用所有角色；只读 / 回放模式与运维模式的差异见下文「两种运行模式」。

> ⚠️ 本平台至今只在「回放数据 + 模拟执行器」下测试过，**从未对真实 TiDB / tiup 集群执行过任何命令**。凡涉及真实命令输出、tiup / pd-ctl / br 参数写法的行为，一律以真实集群联调结果为准；首次上生产前请先在测试环境走一遍全流程（联调清单见 `docs/运维部署手册.md` 12.7）。

## 平台是什么

TiDB 运维平台（TiDB Ops）部署在 tiup 中控机上，提供三类能力：

| 能力 | 说明 | 对应页面 |
|---|---|---|
| 看 | 集群总览、拓扑架构、告警、慢 SQL、热点、诊断结论 | [集群总览](go:overview) / [集群架构](go:arch) / [智能诊断](go:diag) / [SQL 优化](go:sql) / [热点与调度](go:hotspot) |
| 查 | 排障向导、巡检、参数建议 | [故障排查](go:trouble) / [日常运维](go:ops) |
| 改 | 重启、扩缩容、配置变更、主机维护、备份恢复；带审批、定时、审计 | [节点管理](go:nodes) / [变更排期](go:schedule) / [日常运维](go:ops) |
| 装 / 发命令 | 中控机模式下：在页面里一键部署新集群（支持离线），向中控机发带护栏的命令；都要输入中控机 root 密码（只用一次），变更需另一名管理员批准 | [安装部署](go:deploy) / [中控机命令](go:shell) |

所有写操作都不会直接下发命令：先由服务端**规划并做前置检查**，再按「风险 × 环境」走审批，最后经受限执行器（命令白名单 + 审批令牌）执行，全程写入带哈希链的审计日志。

> 💡 平台账号（用户名 / 口令 / 角色，以及用于高风险变更二次确认的 MFA）只用于登录和使用本平台，与 TiDB 数据库里的 SQL 用户和角色是**两套独立的体系**：在平台里创建账号不会在 TiDB 里创建用户。TiDB 自身的权限请看官方文档 [基于角色的访问控制](https://docs.pingcap.com/zh/tidb/stable/role-based-access-control) 与 [权限管理](https://docs.pingcap.com/zh/tidb/stable/privilege-management)（以你集群的版本为准）。

## 两种运行模式

平台启动时有两种互斥的运行模式，由启动参数决定，**页面上无法切换**。

| 对比项 | 只读 / 回放模式 | 运维模式 |
|---|---|---|
| 启动条件 | 不带 `--data-dir` | 带 `--data-dir <目录>` |
| 登录 | 无登录，打开即看 | 必须登录，会话有超时 |
| 能做什么 | 只能查看（后端仅接受 GET / HEAD） | 查看 + 提交变更 + 审批 + 审计 + 用户与角色管理 |
| 写操作按钮 | 部分页面的扩缩容 / 配置 / 维护按钮仍可点，但只是**前端原型模拟，不会作用于集群** | 按角色权限启用 / 置灰；真实走服务端变更引擎 |
| 数据来源 | `--fixtures` = 回放样例数据；不带 = 直连真实集群（只读） | 同左，叠加变更引擎 |
| 执行器 | 无 | `sim`（模拟，回放模式默认）/ `direct` / `sudo`（真实）/ `none`（未配置，写操作被拒） |
| 集群数量 | 只有一个集群，顶栏集群下拉里只有它自己，**没有集群接入**页 | 可以纳管多个集群（最多 20 个，含主集群）；顶栏下拉切换，管理员在「集群接入」页接入 / 管理，见下文「多个集群」与 [集群接入](help:clusters) |

### 怎么判断当前模式

| 看哪里 | 只读 / 回放模式 | 运维模式 |
|---|---|---|
| 顶栏右上角 | 没有「环境 / 写操作 / 用户名 / 退出」这一组标签 | 有：环境标签（生产 / 预发 / 测试）、「写操作已开启」或「只读」、「显示名 · 角色名」、「退出」按钮；这组标签都是**当前所选集群**的 |
| 顶栏页面标题右边的集群下拉 | 只有一个选项（当前集群名与版本），不能切换 | 每个选项是「显示名（环境）」；你能看到多个集群时可切换，只能看到一个时是灰色的 |
| 打开页面 | 直接进入总览 | 先出现登录页（「欢迎登录」） |
| 顶栏数据来源标签（pill） | `回放数据` 或 `真实数据 · 只读`；完全没有后端时是 `产品演示` | 同左（见下方提示） |
| 侧栏「权限与审计」 | 只有静态规格演示（模拟数据） | 有真实的审批策略、审计日志、写操作开关等标签页 |
| 侧栏「平台配置」分组（用户管理 / 角色权限 / 集群接入） | 不显示 | 分组里现在有三项：「用户管理」「角色权限」只对拥有 `users.manage` 或 `audit.view` 的账号显示；「集群接入」只对拥有 `settings.edit` 的管理员显示 |
| 接口 `/api/health` | `readOnly: true` | `ops.enabled: true`，并带 `env` / `exec` / `sim` |

> 💡 数据来源横幅（页面顶部「回放数据」或「真实数据（只读）」）只描述**数据**是回放还是直连，与是否运维模式无关。运维模式下该横幅仍会写着「扩缩容 / 配置变更 / 主机维护等写操作仍是原型模拟」——这句话在运维模式下**不适用**，运维模式的写操作是真实走变更引擎的（用 `sim` 执行器时除外，见下）。

### 执行器：模拟还是真实

| 执行器 | 含义 | 对集群的影响 |
|---|---|---|
| `sim` | 模拟：校验与令牌验证和真实执行器一致，但不启动任何进程，按命令类型生成逼真输出；等待时间压缩到约 2%，每条命令约 1.5 秒 | 无。仅用于演示 / 培训，回放模式启用运维模式时默认使用 |
| `direct` | Web 进程直接执行 tiup / pd-ctl / br | 真实。自检页会给出警告，生产建议用 `sudo` |
| `sudo` | 经 `sudo -u tidb` 调用受限的 `exec --stdin` 入口 | 真实。推荐的生产形态 |
| `none` | 未配置执行器 | 所有写操作被拒绝：「未配置执行器，无法执行变更」 |

顶栏标签、「写操作开关」页的「执行器」行会显示当前执行器，`sim` 时带「模拟：不会对集群做变更」标注。

## 多个集群：顶栏切换与「环境 = 数据范围」

运维模式下，一个平台可以同时管理**多个 TiDB 集群**（最多 20 个，由管理员在 [集群接入](go:clusters) 页接入，详见 [集群接入帮助](help:clusters)）。每个集群有自己的**环境**（测试 / 预发 / 生产）。要记住三件事：

1. **你在页面上看到的一切（总览、节点、变更、告警……）都属于「当前集群」**——也就是顶栏集群下拉里选中的那个。
2. **每个集群各管各的**：数据采集、变更与审批队列、写操作开关（含两名管理员确认）、变更窗口与冻结期、通知渠道、主机池、巡检结果。**全平台共用**的是：用户、自定义角色、审批策略、双人复核提案、审计日志、登录会话（登录一次所有可见集群通用）。
3. **环境 = 数据范围**：你在某个集群里有什么角色，由**该集群的环境**决定（角色是按环境分配的，见下文「用户的最终权限怎么算」）。你在一个集群的环境里没有角色，这个集群对你就**不可见**——下拉里没有它，直接访问得到的提示与「集群根本不存在」完全一样（「集群不存在或无权访问」）。

### 怎么切换集群

**前置条件**：运维模式、已登录，且你能看到至少两个集群（下拉框不是灰色）。

1. 看页面标题右边的集群下拉框。你会看到每个选项形如「预发集群（预发）」，括号里是该集群的环境。下拉框的颜色按当前集群的环境着色（测试绿、预发橙、生产红）；**当前集群是生产环境时**，下拉框旁边还有红底白字的「生产环境」标签。
2. 点开下拉框，选另一个集群。你会看到页面**整页刷新**（如果开着抽屉或有未保存的内容，会先弹出确认框，点「取消」就留在原集群）。
3. 刷新后你会看到：下拉框是新集群，浏览器标签页标题带上新集群名，顶栏的环境标签、「写操作已开启 / 只读」、你的角色都变成新集群的，页面里的数据也都是新集群的；你仍停留在原来的页面。
4. 你的选择记在**这个浏览器**里，下次打开自动回到它；换浏览器或清理站点数据后回到默认集群（主集群，对你不可见时是你可见的第一个集群）。

**后果**：只是换视图，不改服务器上的任何东西，不用重新登录。之后提交的变更、开的开关、改的设置都属于**新集群**。

> ⚠️ 动手前先看顶栏：下拉框的颜色、生产集群的红色「生产环境」标签，以及变更提交面板顶部的「集群 X」标签。下拉框是灰色且悬停提示「当前账号只能看到这一个集群」，说明你只能看到一个集群。如果提示「当前集群已不可用，已切换到默认集群」，说明你正在用的集群被删除了或你在它的环境里的角色被拿掉了，页面已自动回到默认集群；原因与处理见 [常见问题](help:faq) 的「集群相关」。

## 怎么登录

仅运维模式需要登录。平台只支持**本地账号**（只认用户名 + 口令，登录时不需要动态验证码），**没有** LDAP / SSO / 企业微信 / 钉钉 / 飞书登录；账号由管理员在 [用户管理](help:users) 里创建。

**前置条件**

- 平台以运维模式运行，你知道平台地址（向管理员或部署人员要）。
- 你已经有账号：用户名与口令由管理员给你。首次部署时由系统生成的管理员 `admin` 的初始口令只在服务日志里打印一次，见 [权限与审计](help:security) 的「新环境的第一次初始化」。
- 登录**不需要**动态验证码。MFA（动态验证码）只在提交生产高风险变更时用于申请人二次确认，见下文「口令、MFA 与会话的规则」。

**步骤**

1. 在浏览器里打开平台地址。预期结果：出现登录页。左侧是品牌区「TiDB 集群运维平台」，右侧是表单「欢迎登录」（窄屏只显示表单）；表单标题下方有一个环境标签（「生产环境」「预发环境」或「测试环境」）和灰字「所有操作都会被记录审计」。
2. 先看环境标签。登录页的环境标签显示的是**主集群**（平台启动时定义的那个集群）的环境；平台纳管了多个集群时，登录后你可以用顶栏下拉切换到别的集群，各集群的环境见 [集群接入](help:clusters)。**不同平台地址是各自独立的平台、各自独立的账号库**（例如生产平台和测试平台分开部署时），登错平台的口令只会得到「用户名或口令错误」。
3. 在「用户名」框输入用户名。不区分大小写，前后空格会被去掉。如果你以前勾选过「记住用户名」，这里会自动带出上次的用户名，光标直接落在「口令」框。
4. 在「口令」框输入口令。输入框右侧的「👁」按钮可以显示 / 隐藏口令，用于核对有没有输错。如果键盘大写锁定开着，口令框下方会出现「⚠ 大写锁定已开启」。
5. 按需勾选「记住用户名」。勾选后用户名保存在你浏览器本地，下次打开登录页自动填好；**口令永远不保存**。公共电脑请不要勾选；取消勾选后再成功登录一次，已记住的用户名会被清除。
6. 点「登 录」（按钮上的字中间有空格）或在任意输入框按回车。按钮会变成「登录中…」。预期结果：登录页消失，顶栏右侧出现：环境标签、「写操作已开启」或「只读」、「显示名 · 角色名」（多个角色用 `/` 连接）、「退出」。
7. 登录失败时，口令框下方、「记住用户名」上方会出现一行红色提示，口令框会被清空、光标回到口令框，用户名保留。对照下表处理。

**后果**：登录会产生一条审计 `auth.login`（成功记「成功」，失败记「拒绝」，失败记录里的用户名是你输入的用户名）。登录成功后你的「最近登录」时间会更新，管理员在 [用户管理](help:users) 里能看到。

### 登录提示与处理

| 提示 | 出现在哪 | 原因 | 怎么办 |
|---|---|---|---|
| 请输入用户名 / 请输入口令 | 点「登 录」之前，浏览器本地校验 | 对应输入框是空的 | 填写后重试（这类提示不会计入失败次数） |
| 用户名或口令错误 | 服务端返回 | 用户名不存在、口令错、账号已被禁用——平台故意不区分这几种情况，防止被人探测账号 | 核对用户名与口令（点「👁」显示出来看）；仍不行请管理员在 [用户管理](help:users) 里确认账号是否被禁用 |
| 登录失败次数过多，请在 HH:MM:SS 后重试 | 服务端返回 | 同一用户名**或**同一来源 IP 在 10 分钟内连续失败 5 次，被锁定 10 分钟；时间是服务器本地时间 | 见下文「锁定规则」 |
| 登录已过期或已在别处退出，请重新登录 | 登录页顶部的提示框 | 你在已登录状态下会话失效：空闲超过 30 分钟、满 8 小时、管理员禁用 / 改了你的角色 / 重置了你的口令 / 删除了你的账号，你在另一个标签页退出，或平台被重启 | 直接重新登录即可；刚登录就被踢，请联系管理员确认账号状态 |
| 无法连接后端：… | 服务端返回之前 | 浏览器连不上平台（网络 / 代理 / 服务没启动） | 稍后重试；仍不行联系部署人员 |
| 登录失败（502）之类带数字 | 服务端返回 | 反向代理或网关返回了非平台的错误页 | 联系部署人员检查反向代理与平台进程 |

### 锁定规则（为什么我输对了也登录不了）

- 每次登录失败都会同时给「这个用户名」和「你的来源 IP」各记一次。**任何一个**在 10 分钟内累计 5 次，就被锁定 10 分钟。
- 锁定期间，**即使用户名和口令都对也会被拒绝**，提示里的 HH:MM:SS 就是解锁时间；继续输错不会延长也不会缩短锁定。
- 用户名维度的锁定可以由管理员在 [用户管理](help:users) 里点「解锁」立即解除；**IP 维度的锁定管理员也解不了**，只能等它自然结束（最长 10 分钟）。经反向代理访问时，平台看到的来源 IP 往往是代理的地址，别人连续输错也会连累你，详见 [常见问题](help:faq)。
- 任何人都可以对别人的用户名连续输错 5 次来锁定该账号 10 分钟，这是这套机制的副作用；发现无故被锁，联系管理员解锁并看审计日志里该用户名的 `auth.login` 记录与来源 IP。
- 失败计数只在内存里，平台重启后清零。登录成功会清掉该用户名的计数（不清 IP 的）。

### 忘记口令、丢了 MFA 怎么办

登录页的「忘记口令？」链接点开会展开说明（再点一次收起）。**本平台不提供邮件 / 短信自助找回**，按身份分三种情况：

| 你的情况 | 怎么办 |
|---|---|
| 普通账号忘了口令 | 联系平台管理员，在 [用户管理](help:users) 里点你那一行的「重置口令」，设置一个临时口令发给你。用临时口令登录后，立刻到「权限与审计 → 我的账号」改成自己的口令。重置会吊销你所有已登录的会话 |
| 管理员自己忘了口令 | 先看有没有另一名管理员能帮你「重置口令」；没有的话，要有中控机命令行权限的人在**服务停止时**执行 `TIDBOPS_USER_PASSWORD=新口令 tidbops-server user passwd --data-dir <数据目录> --name <用户名>`，再启动服务。完整步骤、占位符说明和注意事项见 [权限与审计](help:security) 的「命令行：忘记管理员口令或丢失 MFA」 |
| 手机丢了 / 换了，动态验证码用不了 | 不影响登录，只影响提交生产高风险变更（需要申请人二次确认）。请管理员在 [用户管理](help:users) 里对你「重置 TOTP」，再到「权限与审计 → 我的账号」重新绑定，绑定完成前无法提交生产高风险变更。管理员自己的 MFA 丢了、又没有其他管理员时，用命令行 `tidbops-server user totp-reset`，见同一节 |

> ⚠️ 登录页展开说明里的命令没有提到「需要重启服务才生效」。运行中的服务不会重新读取命令行改过的用户库，所以请按 [权限与审计](help:security) 里的步骤在服务停止时执行，再启动。命令行操作**不写审计日志**。

### 演示环境的登录

只有后端以 `--dev-seed` 启动（回放演示模式）时，登录页底部才会多出一个「演示环境」区块，其他环境不会出现：

1. 在下拉框「— 选择演示账号 —」里选一个账号（`admin`、`admin2`、`dba`、`sre`、`approver`、`approver2`、`viewer`、`auditor`、`dev`）。预期结果：用户名自动填好。
2. 除 `admin` 外，口令框会自动填入统一演示口令 `Tidbops-Demo-1`，光标落在「登 录」按钮上，直接点即可。选 `admin` 时口令框留空：`admin` 的口令以启动时的设置为准（系统建账号时所有演示账号口令相同，如果 `admin` 的口令被改过，请向演示环境的搭建者询问）。

### 口令、MFA 与会话的规则

| 项 | 规则 |
|---|---|
| 用户名 | 不区分大小写，库内统一为小写 |
| 口令策略 | 至少 10 位、至少 3 类字符（大写 / 小写 / 数字 / 符号）、不得包含用户名、最长 128 位；不满足时会提示具体原因，如「口令至少 10 位」「口令需至少包含大写字母、小写字母、数字、符号中的 3 类」「口令不得包含用户名」 |
| MFA（TOTP） | **不是登录方式**，只用于提交高风险变更时的申请人二次确认（默认只有生产 · 高风险，审批策略里可配）；6 位动态码，30 秒一换，允许前后各 1 个时间窗的误差；绑定步骤见 [权限与审计](help:security) 的「绑定 MFA 的步骤」，算法标准见 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) |
| 动态码只能用一次 | 同一 30 秒时间窗内的验证码只能被接受一次（防重放，RFC 6238 也要求验证方不得重复接受同一个码）：在提交高风险变更或绑定 MFA 时，刚用过的码在同一时间窗内再填会被拒绝，需等下一个码 |
| 会话 | 空闲 30 分钟、绝对 8 小时过期；过期后任何操作会回到登录页，重新登录即可 |
| 退出 | 顶栏「退出」，立即销毁会话 |

> 💡 页面开着时，前端每隔 2–8 秒会自动拉取变更数据，这会不断刷新「空闲」计时；因此只要标签页不关，实际只受 8 小时绝对上限约束。到点后重新登录即可。

### 会话与 CSRF 对你的影响

- 会话 Cookie 为 HttpOnly + SameSite=Strict，放在 HTTPS 反向代理后时应加 `--secure-cookie`。
- 所有写请求（POST）都要带 CSRF 令牌，并校验 `Origin` 与访问的主机一致。你不需要手工处理，页面会自动带上。
- 你会遇到的情况：在另一个标签页登录了别的账号 / 退出登录后，原标签页的令牌失效，操作会提示「CSRF 校验失败」，**刷新页面**即可；通过反向代理访问却提示「拒绝跨站请求」，说明代理改写了 `Host` 头（见 [常见问题](help:faq)）。
- 每个用户写类请求限速每分钟 60 次，超过提示「请求过于频繁」。

## 内置的 7 个角色能做什么

角色按环境授予（测试 / 预发 / 生产可以是不同角色，未单独设置的环境沿用「所有环境」），而**环境就是集群的数据范围**：你在哪个环境有角色，就只能看到、操作那个环境的集群（见上文「多个集群」）。一个人可有多个角色，**最终权限是这些角色能力的并集**（规则见下文「用户的最终权限怎么算」）。**被禁用的账号一律没有任何权限**。

内置角色一句话：

| 角色 | 定位 |
|---|---|
| 访客 | 只读：看总览、拓扑 |
| 开发 | 业务开发：只看自己被授权的库的慢 SQL 与执行计划 |
| 值班 SRE | 值班：看全部、跑诊断巡检、申请实例级操作 |
| DBA | 变更执行：发起并执行扩缩容、配置、维护、备份等变更（经审批） |
| 审批人 | 把关：审批中 / 高风险变更；不能执行变更 |
| 管理员 | 平台管理：用户与角色、平台设置；不能直接做集群变更 |
| 审计员 | 审计：只读审计日志并导出 |

图例：✔ 直接允许；审 = 可以发起，但要按「风险 × 环境」走审批；范 = 仅限被授权范围；— = 无。

| 能力 | 能力键 | 访客 | 开发 | SRE | DBA | 审批人 | 管理员 | 审计员 |
|---|---|---|---|---|---|---|---|---|
| 查看总览 / 拓扑 | `view.overview` | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |
| 查看慢 SQL / 执行计划（含 SQL 文本） | `view.sql` | — | 范 | ✔ | ✔ | ✔ | ✔ | — |
| 运行诊断 / 巡检 / 只读命令 / 告警静默 | `diag.run` | — | — | ✔ | ✔ | ✔ | ✔ | — |
| 导出巡检报告 | `report.export` | — | — | ✔ | ✔ | ✔ | ✔ | — |
| 单实例操作 / 滚动重启 | `inst.op` | — | — | 审 | 审 | — | — | — |
| 扩缩容 / 升级 | `scale` | — | — | — | 审 | — | — | — |
| 配置变更 | `config` | — | — | — | 审 | — | — | — |
| 主机维护 | `maint` | — | — | — | 审 | — | — | — |
| 备份 / 恢复 | `backup` | — | — | — | 审 | — | — | — |
| 创建变更排期 | `sched.create` | — | — | ✔ | ✔ | — | — | — |
| 审批中风险变更 | `approve.mid` | — | — | — | — | ✔ | — | — |
| 审批高风险变更 | `approve.high` | — | — | — | — | ✔ | — | — |
| 平台发布 | `release` | — | — | — | — | — | 审 | — |
| 修改平台设置 | `settings.edit` | — | — | — | — | — | ✔ | — |
| 开启 / 关闭写操作开关 | `writeswitch` | — | — | — | — | — | 审 | — |
| 用户与角色管理 | `users.manage` | — | — | — | — | — | ✔ | — |
| 查看审计日志 | `audit.view` | — | — | — | — | ✔ | ✔ | ✔ |
| 导出审计日志 | `audit.export` | — | — | — | — | — | — | ✔ |
| 中控机命令：执行（中控机模式） | `shell.run` | — | — | — | — | — | ✔ | — |
| 中控机命令：批准变更（中控机模式） | `shell.approve` | — | — | — | — | — | ✔ | — |

要点（职责分离）：

- **管理员不能执行集群变更，也不能审批变更**；审批人不能发起变更；申请人不能审批 / 驳回自己的变更，同一人不能对同一变更重复审批。
- 变更的**取消 / 中止 / 确认人工步骤**只有申请人或内置的 DBA 角色能做；**填写事后复盘**只有申请人能做。
- 「访客」和「审计员」看不到任何慢 SQL；「开发」只能看到管理员为其授权的库（[用户管理](help:users) 里的「授权库」）的慢 SQL。
- 有 `audit.view` 的角色（审批人、管理员、审计员，以及含该能力的自定义角色）还能**只读**查看 [用户管理](go:users) 与 [角色权限](go:roles) 两页（看到用户清单、各环境的角色分配、每个角色的权限），所有写按钮置灰，不能做任何修改。
- 在「权限与审计 → 我的账号」可以看到你当前环境下拥有的全部能力键。
- 矩阵里的「创建变更排期」「平台发布」两项后端目前没有对应的接口检查（提交变更实际按上面的 `inst.op` / `scale` 等能力判定）；以你账号里实际能点的按钮为准。

### 用户的最终权限怎么算

1. 先确定**当前集群的环境**（顶栏环境标签）下生效的角色列表。如果用户在该环境上被「单独设置」了角色，就**只用**这个列表，完全不看「所有环境」的角色；没有单独设置，才用「所有环境」的列表。单独设置却一个角色都不选，该环境下就没有任何角色（这个环境的集群对他不可见）。其他环境里设的角色在当前集群里不起作用。**切换到另一个环境的集群，生效的角色就跟着换**：例如 bob 在「测试」单独设置了 DBA、「所有环境」是访客，则他在测试集群里是 DBA，在预发 / 生产集群里是访客。
2. 再把这个列表里**所有角色**的能力合并（并集）：每项能力取最强的授予方式，强弱顺序是 ✔ 直接允许 > 审（需审批） > 范（范围内）> 无。例如同时有「开发」（慢 SQL 为「范」）和「值班 SRE」（慢 SQL 为 ✔），则慢 SQL 为 ✔。
3. 每个请求都按当前最新的角色与能力判定，不缓存在会话里；管理员改了你的角色，几秒内页面按钮就会跟着变化。

## 自定义角色

内置 7 个角色不够用时（例如「只读审计 + 查看用户，但不能导出审计日志」），管理员可以新建**自定义角色**：一个角色就是一组能力，每项能力选「允许 / 需审批 / 范围内」（该能力支持哪几种以界面为准）。

**谁能做什么**

| 操作 | 谁 | 在哪里 |
|---|---|---|
| 新建 / 复制 / 改名与描述 / 修改权限 / 删除自定义角色 | 拥有 `users.manage` 的账号（目前只有内置「管理员」角色有这个能力） | [角色权限](go:roles)，帮助见 [角色权限](help:roles) |
| 把自定义角色分配给用户 | 同上 | [用户管理](go:users) 的「编辑」或「新建用户」，角色列表里「自定义」一栏 |
| 只读查看角色与成员 | 拥有 `audit.view` 的账号 | [角色权限](go:roles) |

**限制**（后端强制，界面会提前提示）

| 限制 | 说明 |
|---|---|
| 数量 | 最多 50 个自定义角色 |
| 角色 ID | 创建时填写，之后不能改；规则 `^[a-z][a-z0-9_-]{1,31}$`，即 2 到 32 位，小写字母开头，只能含小写字母、数字、`_`、`-`；不能与内置角色的 ID 相同（`viewer` `developer` `sre` `dba` `approver` `admin` `auditor`） |
| 角色名称 | 1 到 40 个字，不区分大小写，不能与已有角色重名，也不能与内置角色的中文名（访客 / 开发 / 值班 SRE / DBA / 审批人 / 管理员 / 审计员）或 ID 相同；说明最多 200 字（可选） |
| 仅管理员能力 | 「用户与角色管理」`users.manage`、「开启 / 关闭写操作开关」`writeswitch`、「修改平台设置」`settings.edit` 只属于内置「管理员」角色，自定义角色不能持有（对管理员自己也一样） |
| 必含「查看总览」 | 每个自定义角色必须含 `view.overview`，否则成员登录后什么都看不到；界面上它是必选项 |
| 授予方式 | `inst.op` / `scale` / `config` / `maint` / `backup` / `release` 可选「允许」或「需审批」；`view.sql` 可选「允许」或「范围内」；其余只能「允许」 |
| 只能授予自己拥有的能力 | 防提权：操作者只能授予自己已拥有、且授予方式不低于所授予方式的能力。目前能改角色的只有内置管理员，而管理员不受这一条限制（上面「仅管理员能力」那条对所有人都生效） |
| 有成员时不能删除 | 只要还有用户（含已禁用的用户，任一环境）持有该角色，删除就会被拒绝并列出成员；先到 [用户管理](go:users) 把成员的角色改掉 |

**生效时间**：修改**即时生效**。保存后，持有该角色的人的**下一次请求**就按新权限判定，不需要他们重新登录，也不会吊销他们的会话。管理员保存前，界面会弹出「新增 / 移除 / 变更」差异和「将立即对 N 名成员生效」的提示，请认真核对。所有新建 / 修改 / 删除都写入审计（`role.create` / `role.update` / `role.delete`，摘要含权限差异），详见 [权限与审计](help:security)。

**自定义角色与内置角色的行为差异**

- 取消 / 中止 / 确认人工步骤只认「申请人本人」或内置 DBA 角色：即使自定义角色有 `backup` / `maint` 等能力，成员也**不能代别人**取消或中止变更（见 [常见问题](help:faq)）。
- 「部署自检」里「至少两名管理员」只统计内置管理员角色。
- 自定义角色被删除（或被人手工改坏了 `roles.json`）后，持有者在该角色上按「无权限」处理；用户管理页里该角色显示为「xxx（已删除）」。
- 顶栏右上角的标签显示的是角色**中文名**（自定义角色显示你给它起的名字），不是角色 ID。

## 风险等级 × 环境 → 审批级别

每个变更先由服务端规划出**风险等级**，再按下表（默认策略，管理员可经双人复核修改，见 [权限与审计](help:security)）决定需要几级审批。

| 风险 | 测试 | 预发 | 生产 |
|---|---|---|---|
| 低 | 免审批 | 免审批 | 免审批 |
| 中 | 免审批 | 1 级 | 1 级 |
| 高 | 1 级 | 2 级 | 2 级，并且申请人需 MFA |

- 紧急变更（冻结期 / 禁止窗口内强行执行）规则固定、不可配置：预发 / 生产**至少 2 级**审批；测试环境没有紧急通道，按常规。
- 「需 MFA」指**申请人**在提交变更时要输入自己的动态验证码；审批人审批时不需要。没绑定 MFA 的人提交高风险变更会被拒绝并提示先去绑定。
- 策略表里取不到的组合一律按最严格（2 级 + MFA）处理。
- 免审批的变更（如低风险）提交后立即执行（选了定时则到点执行），但同样留痕。

各类变更的默认风险（由 `backend/internal/change` 规划器决定）：

| 变更 | 风险 | 备注 |
|---|---|---|
| 启动实例 / 恢复 Leader 调度 | 低 | |
| 重启实例 / 驱逐 TiKV Leader | 中 | TiKV 先驱逐 Leader，重启后恢复调度 |
| 停止实例 | 高 | |
| 扩容 | 中 | |
| 缩容 | 高 | |
| 配置变更 | 中 | 含高危参数（目前仅 `replication.max-replicas`）时标为高风险，但同时会被前置检查直接拦截，见 [常见问题](help:faq) |
| 主机维护：进入 / 结束 / 延长窗口 | 高 / 中 / 低 | |
| 按角色滚动重启 | 中 | |
| 滚动升级 | 高 | |
| 备份：全量 / 启动日志备份 | 中 | |
| 备份：停止日志备份（PITR） | 高 | 停止后无法恢复到停止之后的任意时间点 |
| 从备份恢复 | 高 | |
| 告警静默 | 低 | 不走审批，但受写操作开关约束并写审计 |

## 一次变更的完整生命周期

```
预览（规划 + 前置检查）→ 提交 →（待审批 → 逐级审批）→ [已排期] → 排队中 → 执行中 → 成功 / 失败 / 已中止
                                  └→ 驳回 / 取消 / 过期（终态，不执行）
```

| 阶段 | 发生什么 | 谁 | 你要注意 |
|---|---|---|---|
| 1. 预览 | 在「节点管理」「日常运维」等页点操作，右侧抽屉由服务端规划：前置检查（✔ / ⚠ / ✖）、将执行的命令、执行步骤、需几级审批、窗口检查 | 有对应能力的角色 | 任何一项「✖ 阻断」都会禁用「提交变更」；先处理阻断项 |
| 2. 选执行时间 | 「审批通过后立即执行」或「定时执行…」；抽屉里的「推荐时间」按窗口规则打分，点一下回填 | 申请人 | 勾选「紧急变更」可进入冻结期 / 禁止窗口，但审批更严、事后必须复盘 |
| 3. 提交 | 服务端再次规划并落库，变更编号 `CHG-xxxx`；高风险生产变更要输入动态验证码 | 申请人 | 写操作开关未开启 / 强制只读 / 版本不受支持时无法提交 |
| 4. 审批 | 状态「待审批」；有审批权限的人在「节点管理 → 任务中心」或「变更排期」点「批准 / 驳回」；级数满足后进入下一步 | 审批人 | 审批有效期 24 小时，过期自动作废（定时变更的有效期不早于计划时间） |
| 5. 定时 | 带「定时执行」且审批通过的变更状态为「已排期」，到点自动开始 | 系统 | 窗口规则与冻结期**只在提交时检查**，之后新增冻结期不会自动拦截已排期变更，排期页会标红提示 |
| 6. 排队 | 状态「排队中」：审批通过、等待执行。**同一个集群内串行**，同一时刻只执行一个变更，其余在队列里等；不同集群的变更互不排队、可以同时执行 | 系统 | 同一实例上已有未结束的变更时，新的会被前置检查拦截；已排期的变更在同一实例 / 主机上时间重叠也会被拒绝 |
| 7. 执行 | 状态「执行中」，按步骤逐条经执行器运行命令，实时显示步骤与日志；等待类步骤会探测实例是否 Up、Leader 是否迁出等 | 系统 | 执行开始前会再次检查写操作开关；执行中关闭开关**不会**中断它 |
| 8. 手工确认步骤 | 某些步骤（如从负载均衡摘除 TiDB，仅当「环境与设置」勾选了「集群前有负载均衡」或登记了负载均衡时才有）显示「⏸ 待人工确认」，要你在外部完成后点「我已完成，继续」（平台不会替你做，也不检查你是否做了） | 申请人或 DBA | 最长等 12 小时，超时变更失败 |
| 9. 终态 | 成功 / 失败 / 已中止 / 已驳回 / 已取消 / 已过期 | | 紧急变更在终态后要由申请人填写「事后复盘」 |

### 中止、回滚与失败

- **取消**：只能取消尚未开始的变更（待审批 / 排队中 / 已排期），申请人或 DBA 可操作。
- **中止**：只能中止「执行中」且计划标记为可中止的变更（单实例停止 / 重启、缩容、进入主机维护），申请人或 DBA 可操作；其中缩容一旦进入 `tiup scale-in` 这类标记为「不可中止」的步骤，就不能再中止。扩容、配置变更、滚动重启、升级、备份、恢复的计划本身不支持中止，只能等它结束。
- **回滚**：平台**没有「回滚」按钮**。失败或被中止时，引擎会按计划**尽力执行恢复命令**（如移除 evict-leader 调度、把 store limit 恢复到 15、用变更前的拓扑 edit-config 还原、恢复 PD 的 max-store-down-time），单条恢复命令失败会被忽略并记日志。滚动重启、升级、备份、恢复没有恢复命令，失败后需人工处理。
- 平台在执行中重启，该变更会被标记为「失败」并提示「请核对集群状态后重新规划」，不会自动续跑。

> ⚠️ 失败 / 中止后的「尽力恢复」不保证集群回到变更前状态。TiKV 重启 / 停止 / 缩容失败后务必到 [节点管理](go:nodes) 与 [热点与调度](go:hotspot) 核对 evict-leader 调度、Store 状态是否已恢复；以真实集群联调结果为准。

### 变更窗口、冻结期与推荐窗口

| 概念 | 在哪里配置 | 作用 |
|---|---|---|
| 变更窗口规则 | [环境与设置](go:settings) → 变更窗口规则（需 `settings.edit`） | 按「星期 + 时间段（可跨午夜）+ 风险 + 变更类型」划分：**禁止**（拒绝创建，紧急变更除外并留痕）/ **不建议**（给警告、推荐时降分）/ **推荐**（推荐时加分）。时间按服务器本地时区 |
| 默认规则 | 未自定义时生效 | 备份窗口 01:30–04:00 不建议；工作日 09:00–12:00 与 14:00–18:00 业务高峰不建议（中 / 高风险）；每日 22:00–06:00 夜间低峰推荐 |
| 冻结期 | [变更排期](go:schedule) 右侧「变更冻结期」（需 `settings.edit`） | 冻结期内**非紧急**变更在提交时被拒绝：「计划时间落在变更冻结期「…」内；确需执行请走紧急变更」 |
| 推荐窗口 | 提交抽屉的「推荐时间」 | 在未来 7 天内以 30 分钟为步长找出：避开冻结期、不命中禁止窗口、不与已排期变更在同一资源上重叠，且得分最高的时段（命中推荐窗口加分，命中不建议窗口减分，越晚越低） |

> 💡 窗口规则、冻结期、通知渠道、写操作开关都是**每个集群各自一份**，改之前先确认顶栏当前集群；审批策略（风险 × 环境）则是全平台一份，按集群的环境取对应的列。

## 写操作开关、双人确认与 READONLY 熔断

运维模式下，写操作有三道总闸，**任一道不满足，就不能提交也不能开始执行变更**：

| 总闸 | 说明 | 怎么解除 |
|---|---|---|
| READONLY 熔断文件 | 中控机上存在 `/etc/tidb-ops/READONLY`（路径可由 `--readonly-file` 改）时强制只读，与开关无关，**对所有集群同时生效**；提示「平台处于强制只读（存在 …）」 | 在中控机上删除该文件；紧急止血时 `touch` 该文件即可 |
| 写操作开关（每个集群各自一个） | 默认**关闭**（新接入的集群也是）。开启要**两名不同的管理员**先后确认（1 小时内有效）；**关闭只要一名管理员，立即生效**（熔断）。在生产集群开了，不影响预发集群 | 先切换到目标集群，再到「权限与审计 → 写操作开关」，详见 [权限与审计](help:security) |
| 版本支持矩阵 | 集群版本不在 v7.5 / v8.1 / v8.5 系列时写操作自动降级为只读 | 升级到受支持版本，或联系平台维护者 |

此外还需要已配置的执行器（`sim` / `direct` / `sudo`），否则提示「未配置执行器，无法执行变更」。

> ⚠️ 开启写操作开关后，有权限的账号提交的变更会真正作用于集群（执行器为 `direct` / `sudo` 时）。关闭开关只阻止**新的**提交与新变更的开始，已经在执行中的变更不会被中断。

## 已知限制与易混淆点

| 界面写的是 | 实际是 | 怎么办 |
|---|---|---|
| 运维模式页面顶部横幅「写操作仍是原型模拟」 | 那是数据来源横幅的固定文案，运维模式的写操作走真实变更引擎（执行器为 `sim` 时才是模拟） | 以「权限与审计 → 写操作开关」的「执行器」一行为准 |
| 登录页「演示环境」写着统一口令见下方说明，`admin` 却要自己填口令 | 系统建演示账号时 9 个账号口令相同；登录页对 `admin` 不自动填口令，因为它的口令可能被改过 | 向演示环境搭建者确认 `admin` 的口令 |
| 登录页「忘记口令？」说明里的命令行重设方法 | 命令行改动需要重启服务才对运行中的实例生效，登录页没写 | 按 [权限与审计](help:security) 的步骤在服务停止时执行 |
| 「用户名或口令错误」 | 用户名不存在、口令错、账号被禁用三种情况都显示这一句（与 MFA 无关，登录不看动态验证码） | 见上文「登录提示与处理」 |
| 「权限矩阵」里「创建变更排期」「平台发布」两项 | 后端目前没有对应的接口检查 | 以你账号里实际能点的按钮为准 |
| 顶栏集群下拉像是「只是看看」 | 运维模式下选择集群会整页刷新，并把**你的环境、角色、能力、写开关状态、全部数据**都换成新集群的；之后提交的变更都属于新集群 | 动手前看顶栏下拉的颜色与提交面板里的「集群 X」标签 |
| 变更编号 `CHG-0001` 像是全平台唯一 | 每个集群各自编号，会重复；「排队中」也只在同一集群内串行 | 看变更详情里的集群 / 环境，或审计日志的「集群」列；详见 [集群接入](help:clusters) |
| 取消 / 中止变更的权限写作「申请人或 DBA」 | 实际认的是申请人本人或**内置** DBA 角色，自定义角色即使有同样的能力也不行 | 见 [常见问题](help:faq) |
| 用户管理页对 `audit.view` 账号的 403 说明「审计员账号拿不到列表」 | 后端现已允许有 `audit.view` 的账号只读获取用户与角色列表，这句提示是旧文案（只在列表读取被拒时才会显示） | 以实际能看到列表为准 |

## 术语表

| 术语 | 含义 |
|---|---|
| TiDB | 无状态 SQL 层，接收业务连接，可水平扩展 |
| PD（Placement Driver） | 集群大脑：保存元数据、分配时间戳（TSO）、调度 Region；多数派存活才可用，建议奇数个 |
| TiKV | 分布式事务型存储，数据按 Region 分片、多副本（默认 3） |
| TiFlash | 列存副本，加速分析查询（MPP） |
| TiCDC | 变更数据同步组件，changefeed 把增量同步到下游 |
| Region | 数据分片单位，每个 Region 有多个副本组成一个 Raft 组 |
| Leader / Peer | Raft 组里负责读写的副本叫 Leader，其余叫 Follower / Peer |
| Store | PD 视角下的一个 TiKV / TiFlash 节点，有 Store ID；状态 Up / Offline / Tombstone |
| evict-leader（evict） | 用 PD 的 evict-leader-scheduler 把某 Store 上的 Leader 迁走，重启前后用；恢复调度（unevict）即移除该调度 |
| tiup | TiDB 官方部署与运维工具；平台的执行器最终调用 `tiup cluster …` |
| scale-out / scale-in | 扩容 / 缩容；TiKV 缩容后 Store 先进入 Offline，Region 迁完才变 Tombstone，再 `prune` 清理 |
| reload | 让修改后的配置通过滚动重启生效（`tiup cluster reload`） |
| max-store-down-time | PD 判定 Store 宕机并开始补副本的时限（默认 30 分钟）；主机维护要在此之前结束，否则会触发补副本 |
| store limit | 限制 Region 迁入 / 迁出速度（个 / 分钟），扩容时可调以控制均衡对业务的影响 |
| PITR | 基于日志备份的任意时间点恢复（`br log`） |
| BR | 备份恢复工具（`tiup br`） |
| DB Time | 数据库在 SQL 上花费的总时间，按 SQL 类型分解可看出时间花在哪类语句上 |
| 热点 | 读写集中在少数 Region / Store 的现象 |
| TOTP / MFA | 基于时间的一次性口令 / 多因素认证，用认证器 App 生成 6 位码；本平台只在提交高风险变更时用它做申请人二次确认，不用于登录 |
| 负载均衡层 / 手工登记 | 「集群架构」图里客户端与 TiDB 之间的一层：自动发现的 TiProxy + 管理员手工登记的 HAProxy / LVS / 云 SLB 等；登记只是平台里的记录，不改动负载均衡本身，但会让缩容 / 维护 TiDB 多出「需人工确认」的摘除步骤；每个集群各自一份 |
| 自定义角色 | 管理员在「角色权限」里新建的一组能力；与内置 7 个角色并列，可分配给用户 |
| 并集 | 用户有多个角色时，把这些角色的能力合在一起，同一能力取最强的授予方式 |
| 回放（replay） | 用一份已采集的样例数据包（fixtures）驱动页面，不连接任何集群 |
| 主集群 | 平台启动参数（`--cluster` 等）定义的那个集群；其余集群由管理员在「集群接入」页接入。主集群不能删除，只能改显示名与描述 |
| 本机 tiup 集群 / 远程集群 | 「集群接入」页里的两种接入方式：**本机 tiup**＝在 tiup 中控机上「从本机 tiup 导入」的集群，可做全部运维操作（写开关与审批照常）；**远程接入（只读）**＝手工添加、只填网络地址的集群，平台碰不到它的 tiup / SSH，不能执行变更 |
| 当前集群 | 顶栏集群下拉里选中的集群；页面上的数据、变更、环境、角色、写开关都是它的 |
| 环境（测试 / 预发 / 生产） | 每个集群的属性：决定该集群里你有什么角色（环境 = 数据范围）、适用审批策略的哪一列；没有该环境角色的人看不到这个集群 |
