# 中控机命令

> 💡 在页面里向 tiup 中控机发送命令、实时看到输出，让运维人员不用登录服务器就能完成日常排查和少量变更。需要**运维模式 + 中控机模式**（安装平台时加 `--standalone --local-tiup`，执行器为 `--exec sudo`），权限在「角色权限」里按能力授予：**执行 / 提交申请 / 取消**需要 `shell.run`（中控机命令：执行），**批准他人的变更申请**需要 `shell.approve`（中控机命令：批准变更），**改策略设置**需要 `settings.edit`（仅内置管理员）；只有 `audit.view` 的账号（如审计员）只能看历史与输出。内置「管理员」角色默认同时拥有 `shell.run` 与 `shell.approve`。静态原型、只读模式和远程接入的平台上没有这个入口。

> ⚠️ 这是一个能在中控机上执行命令的功能，**风险高于平台里其他页面**。它不是交互终端，而是带护栏的「一次一批命令」执行器；护栏是基于命令文本的检查，防的是误操作和随手滥用，**不是对抗恶意管理员的安全边界**。请先在测试机上完整走一遍，再用于生产。

## 这个页面做什么

1. 你输入一条或几条命令（每行一条），页面实时告诉你它们的风险级别：**只读**、**变更**、**禁止**，以及将走哪条执行路径。
2. 只读命令：点「执行」直接跑；变更命令：要先填原因、由**另一名管理员**批准，批准只对这一批命令有效、只能用一次；禁止的命令一律拒绝。**都不需要输入 root 密码。**
3. 一律以 **tidb** 身份执行。需要 root 权限的命令在整行开头写 `sudo`（例如 `sudo tail -n 200 /var/log/messages`）；**带 `sudo` 的命令一律按变更处理**（要原因、另一名管理员批准），即使命令本身是只读的。
4. 输出实时显示（口令、密钥、手机号、身份证号等在写盘前就已遮蔽），可筛选、可下载；每次执行都进审计和「执行历史」。

## 前置条件

| 项 | 要求 | 不满足时 |
|---|---|---|
| 平台形态 | 中控机模式；Linux；执行器为 `--exec sudo`；`/etc/sudoers.d/tidbops` 放行了 `shell-exec --stdin` 入口（1.6.0 起随安装 / 升级生成） | 侧栏没有「中控机命令」入口，或页面顶部红色「执行通道不可用」 |
| tidb 的 sudo 免密 | 中控机上 `tidb ALL=(ALL) NOPASSWD: ALL`（tidb-deploy.sh 的前置条件之一） | 页面顶部黄色提示；以 `sudo` 开头的命令和变更命令会失败 |
| 账号权限 | 执行 / 申请 / 取消：`shell.run`；批准：`shell.approve`；改策略设置：`settings.edit`；只看历史与输出：`audit.view`（或持有上述任一项）| 没权限的账号看不到入口；直接访问接口返回 403 |
| 两个人 | 变更命令要另一名持有 `shell.approve` 的账号批准，申请人不能批准自己的申请 | 只有一个人持有 `shell.approve` 时，他提交的变更申请停在「待批准」 |
| systemd-run | 变更命令在临时 systemd 单元里执行（CentOS 7 的 systemd 219 即可） | 执行变更时提示「启动失败」 |

## 怎么用（按步骤）

### 执行只读命令

1. 侧栏「运维 → 中控机命令」。你会看到上方的中控机信息（主机名、系统、执行身份、sudo 免密是否可用）、命令库、输入框、输出区和历史。
2. 在命令库里点一条（如 `tiup cluster list`）或自己输入。尖括号里的内容（如 `<集群名>`）要自己改成真实值，集群名可在「集群架构」或 `tiup cluster list` 里取。
3. 「工作目录」会**自动取 tidb 的家目录**（如 `/home/tidb`），可以修改。
4. 输入框下方实时显示判定：绿色「只读」+「平台进程内」表示点「执行」就跑，不需要密码。
5. 输出区实时出现以 `$ ` 开头的命令行和它的输出，结束时显示退出码。运行中可以点「取消」。
6. 读 root 才能读的日志，整行开头加 `sudo`：`sudo tail -n 200 /var/log/messages`、`sudo journalctl -u chronyd -n 100 --no-pager`。带 `sudo` 的命令一律按变更处理，要走审批；判定里会标出 `sudo` 和「变更」。

### 执行变更命令（需要审批）

1. 输入命令后，判定显示黄色「变更」+「临时单元」，下方出现「变更原因」输入框。
2. 填写原因（必填，会写进审计），点「提交申请」。你会看到「待批准」提示。申请**锁定这一批命令、工作目录、超时和「遇错停止」**，改动任何一项都要重新申请。
3. **另一名管理员**登录后，在同一页面的「待处理的变更申请」里点「批准」。申请 1 小时内要有人批准。
4. 批准后回到申请人的页面，如果输入框里的命令没动，会提示「已批准」；刷新过页面的话，在申请上点「用这个申请执行」。点「执行」，不需要密码。批准后 1 小时内要执行。
5. 执行成功后，这个申请就用掉了；再执行同样的命令要重新申请。

### 看历史与输出

「执行历史」里每行是一次执行（命令已打码，带执行路径）。点「查看」看输出。**看别人的输出需要 `audit.view`，并且会写一条 `shell.output.view` 审计**；下载同样记审计。

## 区域与参数说明

### 命令输入

| 字段 | 含义 | 可选值 / 默认 | 影响 |
|---|---|---|---|
| 命令 | 每行一条，最多 10 条、每条 2000 字符；支持管道和 `&&`、`;` | — | 整批按最严的一条判定；不支持交互、命令替换、here-doc、后台运行 |
| `sudo` 前缀 | 这一行以 root 权限执行 | 只认 `sudo 命令` 或 `sudo -n 命令`，且必须在整行开头 | `sudo -u / -i / -s / -E`、`sudo su`、管道或 `;` 后面的 `sudo` 一律拒绝；**带 `sudo` 的命令一律按变更处理**（需要审批） |
| 每条的超时 | 每条命令最长运行多久，到时被终止 | 30 秒（默认）/ 2 分钟 / 10 分钟 | 超时的命令退出码 124 |
| 工作目录 | 命令在哪个目录下执行 | 自动取 tidb 的家目录，可修改；必须是绝对路径，只含字母数字和 `_ . / -` | 目录不存在时命令报错 |
| 某条失败就停止 | 一条失败后不再执行后面的 | 默认勾选 | 不勾选则全部执行，退出码取最后一条 |

### 执行路径

| 路径 | 什么时候 | 怎么跑 | 限制 |
|---|---|---|---|
| 平台进程内 | 只读命令（默认） | 平台进程经 sudoers 放行的固定入口 `sudo -n -u tidb … shell-exec --stdin` 起一个 tidb 身份的子进程，子进程**自己再判定一遍**，逐条执行（带 `sudo` 的命令是变更，不走这条路径） | 仍在平台服务的沙箱里：文件系统只读、私有 /tmp；平台服务重启时任务中断 |
| 临时单元 | 变更命令；或管理员在「策略设置」里勾了「只读命令也用临时单元执行」 | 同一个入口用 tidb 的 sudo 免密执行 `systemd-run --unit=tidbops-shell-<任务号> … run.sh`，在沙箱之外以 root 起单元；普通行经 `runuser` 切到 tidb，`sudo` 行去掉前缀直接以 root 执行 | 取消 = `systemctl stop` 该单元；平台重启不影响 |

### 风险分级（规则写死在代码里）

| 级别 | 例子 | 处理 |
|---|---|---|
| 只读 | `tiup cluster list / display / audit / check`、`df`、`free`、`uptime`、`ss`、`ps`、`systemctl status`、`journalctl -n`、`ping`、`ls / du / stat`、`find`（起始目录在日志 / 系统信息目录里、不带删除）、`sed`（只放行行号 + `p` / `d` 和 `s/文本/替换/g`）、在日志目录里 `tail / head / grep / cat` | 直接执行（平台进程内） |
| 变更 | `tiup cluster restart`、`systemctl restart`、`kill`、`rm`、`mkdir`、`cp / mv`、`yum`、`curl`、输出重定向到文件、`sed -i`、`find -delete`；**认不出的命令**；**任何带 `sudo` 前缀的命令**（含本身只读的）；以路径调用的命令（如 `/tmp/x/cat`，无法确认是系统自带的程序）；命令前带 `PATH=`、`LD_PRELOAD=` 等环境变量赋值；超出只读写法的 `sed` 脚本（`e` / `w` / `r` 等命令会执行程序或写文件）；`grep -R`、`date -f`、`ip -batch`、`journalctl --file`、`sort --compress-program`、`wc --files0-from` 等会读取任意文件或执行程序的用法 | 需要原因 + 另一名管理员批准，在临时单元里执行 |
| 禁止 | 读密钥与口令（`~/.ssh`、`id_rsa`、`*.pem`、`/etc/shadow`、平台数据目录、`env`）；读业务数据（`mysql`、`dumpling`、`tiup ctl`）；把数据送出去（`scp`、`nc`、带上传的 `curl`）；`tiup cluster exec / edit-config / destroy`；`rm -rf` 根目录或集群数据；关机重启、磁盘分区；改账号、`su`；`sudo` 带 `-u / -i / -s / -E` 或不在整行开头；`tail -f / top / vim`；命令替换 `$(…)`、反引号、here-doc；读文件内容的路径不在日志与系统信息目录里（包括经符号链接指向目录之外的） | 一律拒绝，并列出每条的原因；拒绝也会写进审计 |

策略档位（管理员在页面下方「策略设置」里改，**修改写审计**）：**标准**（默认）— 只读直接执行、变更需审批；**严格** — 只允许只读命令，变更一律拒绝；**宽松** — 变更免审批，仅记录（不推荐）。

「读文件内容」类命令（`cat / head / tail / grep / wc / cut / sort / sed`）只允许读这些位置：`/var/log`、`/tidb-deploy`、`/home/tidb/.tiup/logs`、`/etc/os-release`、`/etc/hosts`、`/etc/chrony.conf`、`/proc/meminfo / cpuinfo / loadavg / uptime`，**数据目录（如 `/tidb-data`）不在其中**，且必须写绝对路径。你们的部署目录不是 `/tidb-deploy` 时，在「策略设置 → 追加的可读目录」里加（如 `/data/tidb-deploy`；系统目录与数据目录不允许加）。

### 输出与留存

| 项 | 说明 |
|---|---|
| 遮蔽 | 口令 / token / access_key、私钥块、连接串里的口令、手机号、身份证号、银行卡号：平台进程内执行时由子进程在**发回之前**逐行遮蔽，临时单元里经 `sed` 在**写盘之前**遮蔽，平台读取时再遮蔽一遍；输出区下方显示「已遮蔽 N 处」。靠位数识别的号码有漏报也有误报（例如 16–19 位的纳秒时间戳会被当成银行卡号） |
| 命令里的口令 | `--password=xxx`、`-pxxx` 在历史、审计和输出里的命令行上自动打码；平台进程内执行的命令不落盘；临时单元用的命令文件在任务结束后由脚本删除 |
| 上限 | 每个任务输出最多 1 MiB（超出截断并注明）；同一账号同时只能运行一批，平台上同时最多 3 批 |
| 保留 | 默认保留 30 天后自动删除任务目录（1–365 天可调）；可选「只存摘要」：结束 10 分钟后只留前 3 行和行数 |
| 存放 | 数据目录下 `shell/jobs/<任务号>/`（权限 0700，属主 tidbops），**没有额外加密**，靠文件权限与遮蔽保护 |

## 执行后果与风险

> ⚠️ **只读命令也会在中控机上以 `tidb` 身份真实执行**（带 `sudo` 的命令一律走审批，批准后在临时单元里以 root 执行）。分级是基于文本的：`cat` 日志目录里的文件可能读到业务字段（应用日志里若记了业务数据）；遮蔽只能挡住常见格式。

> ⚠️ **变更命令会真实改动系统或集群**，且没有回滚。批准人应当看清「命令、工作目录」再批准；批准对一次执行有效。涉及 TiDB 集群本身的重启、缩扩容、改配置，**优先用「节点管理」「变更排期」**：它们有预检、分级审批、写开关和回滚信息。

> ⚠️ **不需要 root 密码意味着什么**：平台进程经 sudoers 以 tidb 身份执行，而 tidb 在中控机上有 sudo 免密，所以持有 `shell.run` 的人经这个页面能做到的事等同于中控机 root。约束它的是两人审批、文本护栏、全程审计和「谁被授予了 `shell.run` / `shell.approve`」。不需要这个功能的环境，可以从 `/etc/sudoers.d/tidbops` 里删掉 `shell-exec` 那一行，页面会显示通道不可用。

> ⚠️ **验证状态**：分级与遮蔽规则、审批流程、接口权限、子进程协议有单元测试；子进程的执行（遮蔽、遇错停止、取消）与临时单元脚本在 bash 里跑通过；**沙箱里经 sudo 起子进程、tidb 的 sudo -n systemd-run、CentOS 7 上 systemd 219 的行为没有在真实机器上验证**。

## 常见问题与注意

| 现象 | 原因 | 处理 |
|---|---|---|
| 侧栏没有「中控机命令」 | 不是中控机模式 / 账号没有权限 / 不是 Linux / 执行器不是 `--exec sudo` | 用管理员账号看 `GET /api/shell/status` 的 `reason` |
| 页面顶部红色「执行通道不可用」 | `/etc/sudoers.d/tidbops` 没有放行 `shell-exec` 入口 | 让运维按部署手册重新生成 sudoers（升级 1.6.0 时自动） |
| 页面顶部黄色「tidb 没有 sudo 免密」 | 中控机上 tidb 没有 `NOPASSWD` sudoers | 让运维开通（tidb-deploy.sh 的前置条件）；开通前 `sudo` 行与变更命令会失败 |
| 判定「禁止」但我觉得是正常命令 | 命中了某条护栏（如在日志里 grep 的路径不在允许目录；写了相对路径；用了 `$(…)`；`sudo` 不在整行开头） | 看判定下方逐条原因；改成绝对路径、拆成多条；需要读的目录用「追加的可读目录」 |
| `ss`、`ip addr` 报 netlink 不支持 | 平台进程内执行受服务单元沙箱限制，旧单元没有 `AF_NETLINK` | 升级后的单元模板已放开；临时办法：勾选「只读命令也用临时单元执行」 |
| 想读业务数据 | 这里不开放 | 用平台已有的只读 SQL 通道（「SQL 优化」等页面） |
| 提示「你已有命令在运行」 | 同一账号同时只能一批 | 等它结束或取消 |
| 提示「命令、工作目录或超时与申请时不一致」 | 申请后改过输入框 | 恢复原样，或重新申请 |
| 任务显示「平台服务重启，任务中断」 | 平台进程内执行的任务随平台进程一起结束 | 重新执行；长任务可勾选「只读命令也用临时单元执行」 |
| 任务显示「状态未知」 | 超过 6 小时没有退出码（被外部杀掉 / 中控机重启过） | 在中控机上看 `systemctl status tidbops-shell-<任务号>` 与任务目录 |

## 已知限制与易混淆点

| 界面 / 文档写的是 | 实际是 | 建议 |
|---|---|---|
| 「只读」 | 只是基于命令文本的判断：没有出现写入类命令 / 参数，不代表对系统绝对无副作用（例如日志轮转触发、命令运行占用资源） | 把它当成护栏，不是保证 |
| 命令库里的命令 | 只是填入输入框的模板，点了不会执行 | 尖括号处要自己改 |
| 取消 | 平台进程内：终止子进程；临时单元：`systemctl stop`。都会终止整批命令，已执行的命令不会回滚 | 取消后看输出确认停在哪一步 |
| 输出「已遮蔽 N 处」 | 按标记估算，可能把原文里的一串 `*` 也算进去 | 仅作提示 |
| 输出「加密保存」 | 目前**没有**对输出文件加密，保护靠 0700 目录权限和遮蔽；「只存摘要」可以减少留存 | 对输出敏感的环境请选「只存摘要」并缩短保留天数 |
| 在这里执行 `tiup cluster …` 等同于「节点管理」 | 不等同：这里没有预检、写开关、回滚信息；平台的变更台账里也不会有记录（只有 shell 审计） | 集群变更优先走「节点管理」 |
| 平台进程内执行与一键部署的 root 密码 | 「一键部署」仍然要输入中控机 root 密码（部署脚本必须以 root 运行）；「中控机命令」不需要 | 两个页面的要求不同是设计使然 |
