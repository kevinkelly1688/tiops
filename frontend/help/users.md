# 用户管理

> 💡 管理「登录本平台」的账号：新建用户、维护资料、按环境分配角色、授权库、重置口令 / TOTP、禁用 / 启用、解锁、删除。**管理员**（内置 admin 角色，需要 users.manage 能力）可以完整操作；**审计员 / 审批人**等带有 audit.view 能力的账号只能只读查看；其他角色看不到本页菜单。**只有运维模式（后端带 `--data-dir`）才有真实的用户库；只读 / 回放模式下本页只有一张说明卡片，不能增删改用户。**

> ⚠️ 本页管理的是**本平台自己的账号**，不是 TiDB 数据库里的账号。在这里新建、禁用、删除用户，对集群里的 `mysql.user`、数据库权限、`root` 口令没有任何影响，反过来也一样。两者的区别见下文「本平台账号与 TiDB 账号是两回事」。

## 这个页面做什么

- 列出本平台的全部用户：账号、姓名、部门、邮箱 / 手机、角色（按环境）、授权库、MFA 是否绑定、状态（正常 / 已禁用 / 已锁定）、最近登录时间。
- 创建用户并给他分配角色；修改用户资料与角色；重置口令；重置动态验证码（TOTP）绑定；禁用 / 启用；解除登录锁定；删除用户。
- 授予「管理员」角色属于高风险操作，必须由**另一名管理员**确认（双人复核提案），确认入口在「[权限与审计](go:security)」的「待确认提案」标签页。
- 角色本身（每个角色能做什么、自定义角色）在「[角色权限](go:roles)」页管理，详见 [角色权限帮助](help:roles)。

### 本平台账号与 TiDB 账号是两回事

| 对比项 | 本页管理的「平台用户」 | TiDB 数据库自己的用户 / 角色 |
|---|---|---|
| 作用 | 登录本平台网页，按角色使用诊断、变更、审批、审计等功能 | 用 MySQL 客户端连接 TiDB 执行 SQL |
| 存放位置 | 平台数据目录下的 `users.json`（口令只存哈希） | 集群里的系统表 `mysql.user` 等 |
| 创建方式 | 本页「＋ 新建用户」或命令行 `tidbops-server user add` | SQL：`CREATE USER`、`GRANT` |
| 角色含义 | 平台自己的 7 个内置角色 + 自定义角色（能力集合） | TiDB 的 RBAC 角色（`CREATE ROLE`，权限集合） |
| 互相影响 | 无。平台用户不会自动获得数据库权限；平台以「只读账号」「运维账号」两个**固定的数据库账号**访问集群，口令来自服务器上的环境变量文件，与用户无关 | 无。数据库账号不能登录本平台 |

了解 TiDB 自身用户与权限体系，请看官方文档：[用户账户管理](https://docs.pingcap.com/zh/tidb/stable/user-account-management)、[基于角色的访问控制](https://docs.pingcap.com/zh/tidb/stable/role-based-access-control)、[权限管理](https://docs.pingcap.com/zh/tidb/stable/privilege-management)（页面均以 stable 为准，**以你集群的版本为准**，必要时把地址里的 stable 换成对应版本，如 v8.1）。

### 谁能看到、谁能操作

| 你的情况 | 侧栏「平台配置」分组 | 本页能做什么 |
|---|---|---|
| 运维模式 + 有 users.manage（内置管理员） | 看得到「用户管理」「角色权限」 | 全部功能 |
| 运维模式 + 只有 audit.view（审计员、审批人，或带 audit.view 的自定义角色） | 看得到 | 只读：能看列表与筛选；「＋ 新建用户」和每行的 6 个按钮全部置灰，悬停提示「需要 users.manage 能力（审计员只读）」 |
| 运维模式 + 两者都没有（访客、开发、值班 SRE、DBA 等） | 整个「平台配置」分组不显示；手工打开本页的网址也只显示「当前账号没有查看用户与权限的能力（需要 users.manage 或 audit.view）。」 | 无。服务端同样拒绝：接口返回 403 并写一条审计 |
| 只读 / 回放模式（没有 `--data-dir`） | 显示 | 只有说明卡片「用户与权限管理需要运维模式（启动参数 `--data-dir`）。当前是原型 / 只读演示模式，没有真实的用户库，这里不提供用户的增删改。」 |

> 💡 能力（users.manage、audit.view 等）是角色的组成部分，完整清单见 [角色权限帮助](help:roles)。注意：审批人角色也带 audit.view，所以审批人同样能只读查看本页与「角色权限」页。

## 先搞清几个概念

| 术语 | 一句话解释 |
|---|---|
| 用户 / 账号 | 登录本平台用的名字，如 `alice`。用户名建好后不能改名 |
| 角色 | 一组能力的集合。内置 7 个：访客、开发、值班 SRE、DBA、审批人、管理员、审计员；管理员还可以建自定义角色 |
| 能力 | 角色里的一项权限，如 `inst.op`（单实例操作）、`approve.high`（审批高风险变更）。一个用户的最终能力 = 他在当前环境下所有角色里**每项能力取最强**的授予方式（允许 > 需审批 > 范围内） |
| 环境 | 每个**集群**属于一个环境（测试 / 预发 / 生产）：主集群的环境由启动参数 `--env` 决定，其他集群的环境由管理员在 [集群接入](help:clusters) 里设置；页面右上角的环境标签是**当前所选集群**的环境。角色可以「按环境」分配，所以**环境就是集群的数据范围** |
| 授权库 | 只对「开发」角色（或把「查看慢 SQL / 执行计划」设为「范围内」的自定义角色）有意义：这个用户可以看哪些数据库的慢 SQL 与执行计划 |
| 会话 | 登录后服务端保存的登录状态（空闲 30 分钟、最长 8 小时失效）。被「吊销」后，对方下一次操作会被要求重新登录 |
| MFA / TOTP | 动态验证码。用户在认证器 App（如 Google Authenticator）里绑定后，提交生产高风险变更（默认策略，审批策略可配）时要填一个 6 位动态验证码。**不用于登录**：登录只认用户名 + 口令 |
| 提案（双人复核） | 授予管理员这类高风险操作不会立刻生效，而是先变成一条「提案」，由另一名管理员确认后才生效，有效期 60 分钟 |
| 锁定 | 同一用户名或同一来源 IP 在 10 分钟内连续输错 5 次，会被锁 10 分钟 |

## 怎么用（按步骤）

以下全部针对**运维模式**。每个会改动的操作都会写审计日志（在「权限与审计」→「审计日志」查看，动作名见各节），**口令、TOTP 密钥永远不会出现在审计里**，邮箱 / 手机 / 备注的内容也不会出现，只记录「更新资料：部门、邮箱」这样的字段名。

### 第 0 步：确认你在哪个页面、有没有权限

1. 登录平台（右上角能看到环境标签、你的角色和用户名）。
2. 点侧栏「平台配置」分组下的「用户管理」。你会看到标题「用户管理」，副标题类似「9 个用户 · 修改角色 / 禁用 / 重置口令 / 删除会吊销其会话」。
3. 如果顶部有蓝色提示「只读：当前账号没有 users.manage 能力，创建 / 编辑 / 禁用 / 重置 / 删除均不可用。」，说明你只有 audit.view，只能查看，找管理员操作。
4. 如果看不到「用户管理」菜单，或打开后是黄色「当前账号没有查看用户与权限的能力」，说明你的角色没有这两项能力，找管理员；或确认你登录的是正确的账号。
5. 页面每隔约 9 秒自动刷新一次列表（你在输入或打开了抽屉时不刷新）；也可以点右上角「刷新」，会提示「已刷新」。

### 一、查看列表、搜索与筛选

**前置条件**：users.manage 或 audit.view。

1. 在「搜索」框输入关键字。它同时匹配「账号 / 姓名 / 部门 / 邮箱 / 手机」，不区分大小写，子串匹配。你会看到表格实时过滤，副标题变成「N / M 个用户」。**备注不参与搜索。**
2. 「状态」下拉选「正常」「已禁用」或「已锁定」，只显示该状态的用户（「已锁定」指用户名维度的登录锁定仍在有效期内）。
3. 「角色」下拉选一个角色（内置角色或带「（自定义）」的角色），只显示在**任一环境**持有该角色的用户。
4. 条件太多时点「清除筛选」恢复。没有匹配时显示「没有符合筛选条件的用户」。
5. 从「[角色权限](go:roles)」页「成员」标签点「在用户管理中查看 →」或某个账号后的「在用户管理中定位 →」跳转过来时，会自动带上角色筛选或账号搜索，需要时点「清除筛选」。

### 二、新建用户

**前置条件**

- 你是管理员（users.manage）。
- 你已经决定：用户名、初始口令（用安全渠道告诉对方）、角色（见下文「角色按环境分配」）、是否需要授权库。
- 要给对方「管理员」角色时，先读「四、授予管理员」：需要另一名管理员确认，并且平台里至少要有两名管理员。

**步骤**

1. 点右上角「＋ 新建用户」。右侧弹出抽屉「新建用户」，分「账号与资料」「角色（环境 → 角色）」两部分。
2. 「用户名（字母 / 数字 / . _ -）」：填登录名，如 `alice`。后端实际规则：2 到 64 位，只能含小写字母、数字、`.`、`_`、`@`、`-`，且以字母或数字开头；填了大写字母会被自动转成小写。建好后**不能改名**。你会看到：规则不符时点「创建用户」会在抽屉底部红字提示「用户名需 2–64 位，只能包含小写字母、数字及 . _ @ - ，且以字母或数字开头」。
3. 「姓名（显示名）」：页面和审计里显示的名字，最多 40 个字；不填则取用户名。
4. 「部门」「邮箱」「手机」「备注」：可选资料，规则见下文「资料字段」。不确定时可以先空着，之后在「编辑」里补。
5. 「初始口令（≥10 位、≥3 类字符、不含用户名）」：填一个满足口令策略的口令。输入时下面一行会实时提示：红字「不满足：至少 10 位（当前 4）；至少 3 类字符（当前 1 类）」或绿字「格式符合口令策略（最终以后端校验为准）」。
6. 「角色（环境 → 角色）」：默认只勾了「所有环境（默认）」下的「访客」。按需勾选；要给不同环境不同角色，勾「测试」「预发」「生产」各自的「单独设置」后再选。至少要为一个环境选一个角色，否则提示「请至少为一个环境选择一个角色」。
7. 需要给「开发」角色（或「范围内」授予 view.sql 的自定义角色）配置授权库时，在「开发角色可查看 SQL 的库（逗号分隔）」填库名，例如 `shop, pay`。其余用户留空。
8. 点「创建用户」。**你会看到**：抽屉关闭，右上角提示「已创建用户 alice」，列表里出现新用户，状态「正常」，最近登录「从未登录」，MFA「未绑定」。
9. 如果勾了「管理员」，你会看到的是橙色提示：「用户 alice 已创建（不含管理员角色）。…授予管理员角色需要另一名管理员在「权限与审计 → 待确认提案」里确认后才生效。」旁边有按钮「去看提案」。此时 alice 已经存在，只是**还没有**管理员角色。
10. 把用户名与初始口令用安全渠道告诉对方，并要求他首次登录后立刻到「权限与审计」→「我的账号」→「修改口令」改掉。平台没有「首次登录强制改口令」的开关。

**后果**：账号立即可用（有管理员角色的除外）；写审计 `user.add`（风险「高」，摘要含创建时的角色）。**撤销**：没有「撤销创建」，只能「禁用」或「删除」（见后文）。

**失败怎么办**：失败信息显示在抽屉底部红字，抽屉不会关闭，改完直接再点「创建用户」。

| 红字（或后端返回） | 含义与处理 |
|---|---|
| 请填写用户名 / 口令至少 10 位 | 前端检查，补全即可 |
| 用户已存在 | 该用户名已被占用（用户名不区分大小写）。换一个名字 |
| 口令需至少包含大写字母、小写字母、数字、符号中的 3 类 / 口令不得包含用户名 / 口令至少 10 位 / 口令最多 128 位 | 口令策略，见下文 |
| 用户资料不合法：… | 邮箱 / 手机 / 长度等资料字段不合规，见「资料字段」 |
| 未知角色 "xxx" | 角色已被别人删除，刷新页面后重选 |
| 请求过于频繁 | 每个账号每分钟最多 60 次写请求，稍等再试 |
| 未登录或会话已过期 | 登录已失效，重新登录 |

### 三、编辑用户（资料、角色、授权库）

**前置条件**：users.manage；**不能编辑自己的角色**（见下文「自保护规则」，自己只能改资料）。

1. 在列表里找到用户，点该行「编辑」。抽屉标题「编辑用户：alice」，顶部「账号」只读，不能改名。
2. 改「姓名（显示名）」「部门」「邮箱」「手机」「备注」，和 / 或改「角色（环境 → 角色）」「开发角色可查看 SQL 的库」。
3. 点「保存」。如果什么都没改，抽屉里提示「没有任何改动」。
4. **你会看到**（关键）：页面实际发出**两个相互独立的请求**，按有没有改动分别发送：资料有改动就发「资料」请求（资料里**任何一个字段**不合规，整次资料修改都不保存，不会只保存其中合规的字段）；角色或授权库有改动就发「角色」请求。两个请求的结果分别显示，可能**一个成功、一个失败**，例如「✖ 资料未保存：用户资料不合法：邮箱格式不正确（形如 name@example.com，不超过 120 位）」与「✔ 角色 / 授权库已保存（其会话已吊销）」同时出现。出现任何失败时抽屉保持打开，已成功的部分**已经生效**；改正失败的字段后再点「保存」，只会重发还没保存的部分。全部成功时抽屉关闭，提示「已更新 alice 的资料与角色」之类。
5. 改了角色或授权库并成功后，该用户**所有现有会话立即被吊销**，对方下一次操作会被要求重新登录（审计 `user.roles`，风险「高」，摘要里写明新的角色集合与「已吊销其会话」）。只改资料不会吊销会话（审计 `user.profile`，风险「中」）。
6. 如果这次角色变更会让用户**新获得管理员角色**，角色请求不会直接生效，而是提交为提案，见下一节。**此时本次提交的所有角色改动（含其他角色、授权库）都一起作为提案等待确认，确认前用户的角色保持不变**；资料改动照常立即保存。

**撤销**：没有「撤销」按钮；再编辑一次改回去即可（再次吊销会话）。

### 四、授予管理员（双人复核提案）

**为什么要这样**：管理员能管理用户、角色、平台设置、写操作开关。为防止一个人悄悄给自己或同伙提权，平台规定：凡是**让某个用户新获得管理员角色**的操作（新建用户时勾管理员；编辑时给某环境新增管理员），都要**另一名管理员**确认。降级（去掉管理员）与其他角色改动不需要确认，立即生效。

**前置条件**

- 平台里至少有**两名**启用中的管理员（发起人与确认人不能是同一个人）。只有一名管理员时，提案永远没人能确认，会 60 分钟后自动作废；此时请用命令行给第二个人创建管理员（见「十、命令行」，注意它不走双人复核）。
- 发起人：users.manage。确认人：另一名有 users.manage 的管理员。

**发起（你）**

1. 新建用户或编辑用户时勾选某环境下的「管理员（需另一名管理员确认）」。勾选后表单里出现橙色提示「授予管理员需要另一名管理员确认（所有环境）。」括号里是涉及的环境。
2. 点「创建用户」或「保存」。**你会看到**：抽屉关闭，列表上方出现橙色提示，例如「用户 alice 的角色变更已提交为提案，确认前其角色保持不变。授予管理员角色需要另一名管理员在「权限与审计 → 待确认提案」里确认后才生效。」，右上角也有一条提示，并有按钮「去看提案」。新建的情况是「用户 alice 已创建（不含管理员角色）…」。
3. 提案编号形如 `PRP-0001`。把编号告诉另一名管理员，请他在 60 分钟内处理。

**确认（另一名管理员）**

1. 登录后到「[权限与审计](go:security)」，默认就是「待确认提案」标签页（标签上有数字角标；侧栏「权限与审计」旁也有红色角标，数字是待**你**确认的数量）。
2. 找到提案卡片：标题「授予管理员」，显示发起人、发起时间、剩余有效时间，下面有表格对比各环境「当前角色」与「确认后的角色」，新增管理员的行有红色「新增管理员」标签。逐行核对：是不是你认可的人、环境是否合理。
3. 点「确认并生效」，在弹出的确认框「确认提案 PRP-xxxx」点「确认并生效」。**你会看到**提示「提案 PRP-xxxx 已确认并生效」，卡片移入下方「最近历史」，状态「已生效」。
4. 不同意就点「拒绝」，在抽屉「拒绝提案 PRP-xxxx」里可填「拒绝原因（选填，最多 200 字，会显示在历史里）」，点「确认拒绝」。

**撤回（发起人）**：到同一页，自己发起的提案上按钮是「撤回」（不是「拒绝」），点后「确认撤回」，状态「已撤回」。用户页没有撤回入口。

**后果**

- 确认后立即生效：用户拿到提案里**确认时的完整角色集合**，同时他的所有会话被吊销，需要重新登录（审计 `user.roles`，摘要含「两名管理员确认（发起人 …）」；提案本身的创建 / 确认 / 拒绝 / 撤回 / 过期写审计 `proposal.create` `proposal.confirm` `proposal.reject` `proposal.cancel` `proposal.expire`）。
- 提案 60 分钟内没人确认，自动变「已过期」，作废；需要重新发起。
- 对同一个用户重新发起新提案，会把旧的待确认提案标为「已撤回」（备注「被 xxx 发起的新提案取代」）。
- 如果发起后、确认前，这个用户的角色又被别人改过，确认时会失败，提案变「已拒绝」，备注「确认时无法应用：用户 alice 的角色在提案发起后已被修改，请基于最新角色重新发起」；用户已被删除则备注「用户 alice 已不存在」。
- 发起人自己点确认会被拒绝：「需要另一名管理员确认：发起人不能确认自己的提案」。
- 提案内容里**不含口令**。

**特别提醒**：新建用户时如果除了管理员没有选其他角色，这个用户会先以「没有任何角色」创建出来（能登录但什么都看不到），直到提案被确认。想让他先有点权限，就同时勾一个别的角色。

### 五、重置口令

**适用场景**：用户忘了口令；怀疑口令泄露。**自己的口令不能在这里重置**，请用「权限与审计」→「我的账号」→「修改口令」（需要输入当前口令）。

**前置条件**：users.manage；目标不是你自己（自己那一行的「重置口令」置灰，悬停提示「不能对自己的账号执行该操作（改自己的口令 / MFA 请到「权限与审计 → 我的账号」）」）。

1. 点该用户行的「重置口令」。抽屉「重置口令：alice」，顶部橙色提示「重置后该用户的所有会话会被吊销，需用新口令重新登录。」
2. 「新口令（≥10 位、≥3 类字符、不含用户名）」填一个新口令。下方实时提示是否满足策略。
3. 点「重置口令」。**你会看到**抽屉关闭，提示「口令已重置，其会话已吊销」。口令不足 10 位时抽屉里红字「口令至少 10 位」；其余策略问题以后端返回为准。
4. 用安全渠道把新口令告诉用户，要求他登录后立刻在「我的账号」改成自己的口令。

**后果**：旧口令立即失效，所有会话被吊销（审计 `user.password`，风险「高」，摘要「重置口令，已吊销其会话」，不含口令）。**不会**清除锁定、不会改变 TOTP 绑定。**不可撤销**：旧口令无法找回。

### 六、重置 TOTP

**适用场景**：用户换了手机、认证器里的密钥丢了，提交生产高风险变更时无法提供 6 位动态验证码（不影响登录）。

**前置条件**：users.manage；该用户已绑定 MFA（「MFA」列显示「已绑定」，否则按钮置灰并提示「该用户未绑定 MFA」）。对自己的账号页面没有限制（「我的账号」里没有重置按钮，丢了认证器的管理员只能在这里重置，或请另一名管理员重置）。

1. 点该用户行的「重置 TOTP」。确认框「重置 TOTP」：「确认重置用户 alice 的动态验证码绑定？重置后需要其重新绑定。」
2. 点「确认重置」。**你会看到**提示「已重置 alice 的 TOTP」，该行 MFA 变回「未绑定」。
3. 通知用户：登录不受影响（仍只需用户名 + 口令），但重新绑定之前无法提交生产高风险变更；请他登录后到「权限与审计」→「我的账号」→「多因素认证（TOTP）」→「开始绑定」，用认证器扫描 / 手工输入显示的密钥，再输入当前 6 位码，点「确认绑定」。**绑定只能由用户自己完成，管理员不能代绑。**

**后果**：绑定信息（含未完成的绑定）被清除；**不会吊销**该用户已有的会话（审计 `user.totp-reset`，风险「高」）。在用户重新绑定之前，如果平台策略要求「申请人 MFA」（默认生产环境的高风险变更），他提交这类变更时会提示先去绑定。**不可撤销**：旧密钥无法恢复，只能重新绑定。

### 七、禁用与启用

**适用场景**：人员离岗 / 账号暂停使用，但要保留账号与审计关联；需要立刻让某人下线。

**前置条件**：users.manage；目标不是你自己（悬停提示「不能禁用自己的账号」）；不是**最后一名启用中的管理员**。

1. 点该用户行的「禁用」。确认框「禁用用户」：「确认禁用用户 alice？其现有会话会被吊销。」
2. 点「确认禁用」。**你会看到**提示「已禁用 alice」，状态变红色「已禁用」，该行按钮由「禁用」变成「启用」。
3. 恢复时点「启用」，确认框「启用用户」，点「确认启用」，提示「已启用 alice」，状态回到「正常」。

**后果**

- 禁用：立即吊销所有会话，且在被启用前无法登录（登录页的提示仍是笼统的「用户名或口令错误」，不会告诉他是被禁用）。他的角色与资料保留，但**任何能力判定都按「无权限」处理**。他已经提交的变更不会被自动取消（由申请人或 DBA 自行取消）。审计 `user.disable`，摘要 `disabled=true`。
- 启用：不会恢复旧会话，用户要重新登录；审计 `user.disable`，摘要 `disabled=false`。可随时反向操作，因此**可撤销**。
- 被禁用的管理员**不计入**「至少两名管理员」自检与「最后一名管理员」判断，但仍计入自定义角色的「成员」（所以仍会阻止删除该角色）。

**失败**：红色提示「禁用失败：不能删除、禁用或降级最后一个管理员」，说明你要禁用的是唯一一名启用的管理员，先给别人授予管理员（走双人复核）再操作。

### 八、解锁

**什么时候会被锁**：同一用户名在 10 分钟内连续登录失败 5 次（只统计口令错误；登录不看动态验证码），该用户名被锁 10 分钟；**同一来源 IP** 也有独立的计数，同样是 10 分钟内 5 次失败就锁 10 分钟（锁住该 IP 上所有人的登录）。被锁时登录页提示「登录失败次数过多，请在 HH:MM:SS 后重试」（HTTP 429）。

**前置条件**：users.manage；该用户**当前处于用户名维度的锁定中**，列表状态显示「已锁定」并在下方小字「至 HH:MM:SS」（悬停提示「登录失败次数过多，锁定至 …」）。未锁定时按钮置灰，提示「该用户当前未被锁定」。

1. 在「状态」下拉选「已锁定」，或在列表里找到状态为「已锁定」的用户。
2. 点该行「解锁」（没有二次确认）。**你会看到**绿色提示：「已解锁 alice。注意：解锁只清除「用户名」维度的失败计数；同一 IP 连续失败仍可能被限流（HTTP 429，最长 10 分钟），届时请稍后再试。」
3. 告诉用户用正确的口令重试。如果仍提示「登录失败次数过多」，说明是**IP 维度**的限制，等它到点（最长 10 分钟）。

**后果**：清除该用户名的登录失败计数与锁定（登录失败计数只含口令错误），同时清除另一个独立的「动态验证码二次确认」失败计数（提交高风险变更或绑定 MFA 时输错验证码 5 次触发的锁，列表上不显示，但解锁会一并清掉）。审计 `user.unlock`，风险「中」，摘要「解除登录锁定（原锁定至 HH:MM:SS）」。**不会**清除 IP 维度的计数。

> ⚠️ 「已锁定」只反映**用户名维度**。如果用户列表里显示「正常」，但他仍无法登录且提示「登录失败次数过多」，那是 IP 维度的锁：「解锁」按钮是灰的、也清不掉，只能等待最长 10 分钟。锁定状态只保存在服务进程内存里，重启服务会清空，但会同时让所有人退出登录，不建议为此重启。

### 九、删除

**适用场景**：账号确认不再需要（如误建、离职已久）。**暂时不用请优先「禁用」**。

**前置条件**：users.manage；目标不是你自己（悬停提示「不能删除自己的账号」）；不是最后一名启用中的管理员。

1. 点该用户行（红色）「删除」。确认框「删除用户」：「确认删除用户 alice？不可恢复，其会话会被吊销（历史审计记录保留）。」
2. 点「确认删除」。**你会看到**提示「已删除用户 alice」，该行从列表消失。

**后果**：用户记录（含口令哈希、TOTP 绑定）被删除，**不可恢复**，所有会话吊销。审计 `user.delete`（风险「高」），历史审计记录里原来的用户名保留。他已提交的变更仍保留申请人名字。**同一用户名之后可以被重新创建**，新账号与旧账号没有任何关系，但审计与变更历史里的名字会相同，所以不建议复用已删除的用户名。

**失败**：「删除失败：不能删除、禁用或降级最后一个管理员」，同「禁用」处理。

### 十、用命令行管理用户（服务器上）

页面之外还有命令行 `tidbops-server user …`，主要用于：首次部署创建管理员、创建第二名管理员（绕过双人复核的「先有两人」问题）、管理员自己忘了口令。登录页点「忘记口令？」也会看到这些说明。

| 子命令 | 作用 | 说明 |
|---|---|---|
| `user add` | 新建用户 | 参数 `--name`、`--display`、`--role`（可逗号分隔多个，内置角色或自定义角色 id）、`--env`（默认 `*`，只能写**一个**环境键）、`--db`（授权库，逗号分隔）；口令从环境变量 `TIDBOPS_USER_PASSWORD` 读取，必须满足口令策略 |
| `user passwd` | 重设口令 | 同样用 `TIDBOPS_USER_PASSWORD`；加 `--insecure-password` 可跳过口令强度策略，**仅限本机演示 / 开发** |
| `user disable` / `user enable` | 禁用 / 启用 | |
| `user totp-reset` | 重置 TOTP | |
| `user list` | 列出用户 | 显示账号、显示名、部门、角色、是否绑定 TOTP、是否禁用、最近登录 |

公共参数 `--data-dir <数据目录>` 必填（部署示例里是 `/var/lib/tidbops`）。没有 `delete`、`unlock`、改资料、改角色的子命令。完整示例见 [安装部署帮助](help:deploy)。

```bash
sudo -u tidbops env TIDBOPS_USER_PASSWORD='<满足口令策略的口令>' /opt/tidbops/current/bin/tidbops-server user add --data-dir /var/lib/tidbops --name bob --role admin
```

- `<数据目录>`：启动平台时 `--data-dir` 指定的目录，部署后默认 `/var/lib/tidbops`；`bob` 换成你要创建的用户名。
- 命令成功会打印「完成」，失败打印「失败: …」并返回非零。

> ⚠️ 命令行与页面的关系：命令行**直接改 `users.json` 文件**，**不会写审计日志**，**不经过双人复核**（`--role admin` 直接生效），并且**运行中的服务不会感知文件变化**：服务把用户库放在内存里，下一次它保存用户库（例如有人登录、任何用户操作）时，会用它内存里的版本整体覆盖文件，命令行刚做的修改可能被悄悄冲掉。因此：**要在服务运行期间用命令行改用户，请先停止服务（`systemctl stop tidbops`），改完再启动**；日常尽量用页面操作。以上行为来自代码，没有在真实部署上验证，以真实联调为准。

## 区域与参数说明

### 列表每一列

|---|---|

| 部门 | 资料，没填显示「—」 |
| 邮箱 / 手机 | 邮箱在上、手机在下，没填显示「—」 |

| 授权库 | 用户可查看慢 SQL 的库列表，没有显示「—」 |
| MFA | 「已绑定」或「未绑定」 |

| 最近登录 | 最近一次**登录成功**的本地时间；从未登录显示「从未登录」。服务端为减少写盘，30 秒内的重复登录不会立刻落盘 |

### 用户状态

| 状态 | 含义 | 能否登录 |
|---|---|---|
| 正常 | 启用中、未被用户名维度锁定 | 能 |
| 已禁用 | 管理员禁用，会话已吊销 | 不能，直到被「启用」 |
| 已锁定（至 HH:MM:SS） | 用户名维度连续失败 5 次，锁 10 分钟，到点自动解除 | 到点之前不能；管理员可「解锁」提前解除 |

### 新建 / 编辑字段

| 字段 | 含义 | 规则（后端校验为准） |
|---|---|---|
| 用户名 | 登录名，不可改 | 2–64 位，小写字母 / 数字 / `.` `_` `@` `-`，以字母或数字开头，自动转小写，不能与现有用户重复 |
| 姓名（显示名） | 显示名 | 最多 40 个字；留空则回退为用户名 |
| 部门 | 资料 | 最多 40 个字（页面输入框允许输到 60，超过 40 会被后端拒绝） |
| 邮箱 | 资料 | 可空；形如 `name@example.com`，不超过 120 位 |
| 手机 | 资料 | 可空；3–30 位，只能含数字与 `+` `-` `(` `)` 和空格 |
| 备注 | 资料 | 最多 200 个字，可含换行；不在列表里显示，不参与搜索 |
| 初始口令 | 仅新建时填 | 见下文「口令策略」 |
| 角色（环境 → 角色） | 见下文 | 至少一个环境有角色 |
| 开发角色可查看 SQL 的库 | 授权库，逗号分隔 | 例 `shop, pay`；按库名**完整匹配**（不区分大小写），不支持通配符；对所有环境统一，不能按环境分别设置 |

资料字段里除备注外不能含控制字符。

### 口令策略

- 至少 10 位，最多 128 位。
- 小写字母、大写字母、数字、其他符号（含中文等）这 4 类里**至少包含 3 类**。
- 不得包含用户名（不区分大小写）。
- 页面输入时的提示只是前端的预检，**最终以后端校验为准**；重置口令与「我的账号」→「修改口令」使用同一套策略。
- 平台只保存口令的 PBKDF2-SHA256 哈希，管理员也看不到任何人的口令。

### 角色按环境分配（含举例）

「角色（环境 → 角色）」有四行：「所有环境（默认）」「测试」「预发」「生产」。规则：

- **当前所选集群的环境**（右上角环境标签，比如「生产」）决定使用哪一行：**如果该环境勾了「单独设置」，就只用这一行的角色；否则沿用「所有环境（默认）」那一行**。「单独设置」是**覆盖**，不是叠加。
- 勾了「单独设置」但一个角色都不选，表示该环境**没有任何角色**（这个环境的集群对他不可见，登录后什么都看不到），也会覆盖「所有环境」。
- 同一环境里可以勾多个角色，最终能力是它们**每项能力取最强**授予方式的并集。
- 用户库与角色库是**全平台一份**（所有集群共用），按**用户 + 环境**记录角色。一个环境可以对应**多个集群**（例如两个预发集群都属于「预发」），用户在这些集群里的角色相同；用户在你切换到的那个集群的环境下是什么角色，就在该集群里拥有什么权限。
- 不同的平台部署（例如生产平台、测试平台分开部署）各有各的数据目录与用户库，互不相通。

举例（alice 在三个**环境**的集群里分别看到什么；假设平台里有测试、预发、生产环境的集群各一个）：

| 设置 | 在测试环境的集群 | 在预发环境的集群 | 在生产环境的集群 |
|---|---|---|---|
| 「所有环境」= 值班 SRE | 值班 SRE | 值班 SRE | 值班 SRE |
| 「所有环境」= 访客；「生产」单独设置 = DBA | 访客 | 访客 | DBA（**不再**同时是访客，但 DBA 本来就包含访客的全部能力） |
| 「所有环境」= DBA；「生产」单独设置 = 访客 | DBA | DBA | 访客（生产环境被降级） |
| 「所有环境」= DBA；「生产」单独设置，什么都不选 | DBA | DBA | 没有任何角色，什么都看不到 |
| 「所有环境」= 值班 SRE + 审批人 | 两个角色并集 | 两个角色并集 | 两个角色并集 |

#### 环境对应哪些集群、谁能看到哪个集群

假设平台里接入了三个集群（见 [集群接入帮助](help:clusters)）：主集群 `prod-tidb-01`（环境：预发）、`stg`（预发）、`dev`（测试）。**可见**的规则是：用户在该集群的环境下至少有「查看总览」能力（所有内置角色都有）。

| 用户的角色设置 | 他能看到哪些集群 | 在各集群里的角色 |
|---|---|---|
| 「所有环境」= 值班 SRE | prod-tidb-01、stg、dev（三个） | 三个集群里都是值班 SRE |
| 「所有环境」= 访客；「测试」单独设置 = DBA | 三个都能看到 | dev 里是 DBA；prod-tidb-01 与 stg 里是访客 |
| 只设置了「测试」= 开发，「所有环境」没设 | 只看到 dev | 只在 dev 里是开发；另外两个集群对他不可见（下拉里没有；直接访问得到「集群不存在或无权访问」，与不存在时一模一样） |
| 「所有环境」= DBA；「预发」单独设置，什么都不选 | 只看到 dev | 预发环境没有任何角色，所以 prod-tidb-01 与 stg 对他不可见 |

要点：

- 给某人开放某个集群，就在**该集群的环境**上给他角色；想收回，就去掉该环境上的角色（或把该环境改成「单独设置」且不选角色）。**改了集群的环境（在「集群接入」里编辑）会立即改变所有用户在该集群里的角色与可见性**。
- 用户只在某个环境有角色时，登录后落在他能看到的第一个集群；顶栏下拉里只有他可见的集群。他正在用的集群因角色被拿掉而不可见时，页面会提示「当前集群已不可用，已切换到默认集群」。
- **本页（用户管理）、「角色权限」页、审计日志、审批策略与双人复核提案、「集群接入」都是全局的，授权按主集群的环境判断。** 也就是说，管理员要在**主集群的环境**里有 users.manage / settings.edit，才能管理用户和集群。内置管理员通常设置在「所有环境」，不会有问题；如果某个管理员只在某个非主集群的环境里有角色（例如只在「测试」是管理员，主集群是预发），他能看到测试集群，切到测试集群后侧栏甚至还会显示「用户管理」菜单（菜单按当前集群的环境显示），但打开页面会被拒绝：**管不了用户、角色和集群接入**。授予管理员角色时请优先设在「所有环境」。
- 写操作开关、变更与审批队列等是每个集群各自的，与用户管理无关；见 [权限与审计](help:security)。

### 自保护规则

| 规则 | 页面表现 | 后端是否也强制 |
|---|---|---|
| 不能禁用自己、不能删除自己 | 自己行的「禁用」「删除」置灰，提示「不能禁用自己的账号」「不能删除自己的账号」 | 仅页面。后端只强制下一条 |
| 不能重置自己的口令 | 「重置口令」置灰，提示改去「我的账号」（「重置 TOTP」对自己没有这个限制） | 仅页面 |
| 不能修改自己的角色 | 编辑自己时角色区域全部禁用，提示「不能修改自己的角色（避免把自己降权后无法恢复）；请让另一名管理员操作。这里只能修改自己的资料。」 | 仅页面 |
| 不能删除、禁用或降级最后一名管理员 | 页面不预判，操作后显示后端错误「不能删除、禁用或降级最后一个管理员」 | 是。统计的是**启用中且在任一环境持有 admin 角色**的用户 |

### 各操作对会话、审计的影响汇总

| 操作 | 会话是否被吊销 | 审计动作（风险） | 能否撤销 |
|---|---|---|---|
| 新建用户 | — | `user.add`（高） | 否（可禁用 / 删除） |
| 改资料 | 否 | `user.profile`（中） | 再改回去 |
| 改角色 / 授权库 | **是** | `user.roles`（高） | 再改回去 |
| 授予管理员（提案确认后） | **是** | `proposal.*` + `user.roles`（高） | 再降级 |
| 重置口令 | **是** | `user.password`（高） | 否 |
| 重置 TOTP | 否 | `user.totp-reset`（高） | 否，需重新绑定 |
| 禁用 | **是** | `user.disable`（高） | 「启用」 |
| 启用 | 否 | `user.disable`（高） | 「禁用」 |
| 解锁 | 否 | `user.unlock`（中） | 否 |
| 删除 | **是** | `user.delete`（高） | 否 |

> 💡 **改了角色之后对方会怎样**：改「用户」的角色会吊销他的会话，对方下一次点击就会回到登录页（提示会话已过期）。而**修改自定义角色本身的权限**（在「角色权限」页）不吊销会话，但每次请求都按最新权限判定，对该角色所有成员**立刻生效**，无需重新登录。

## 执行后果与风险

> ⚠️ 本页所有写操作立即生效、立即落盘，没有「草稿」与「预览」；除「启用 / 禁用」和「再次编辑」外都没有一键回滚。关键提醒：

- 给人**多授予一个角色 = 多给一份权限**。授予 DBA / 值班 SRE 的人可以发起生产变更，授予审批人的人可以批准别人的变更，请对照 [角色权限帮助](help:roles) 逐项确认。
- 重置口令、禁用、删除、改角色都会让对方立刻掉线；对方可能正在处理故障，操作前先沟通。
- 管理员是最高权限，建议只保留 2 到 3 名，并让他们使用 MFA。授予管理员必须双人确认，但**命令行不受此限制**，务必控制服务器登录权限。
- 本页与「角色权限」页没有「变更窗口 / 审批」：这类操作不走变更引擎，也不受「写操作开关」「READONLY 熔断文件」限制——即使整个平台处于只读状态，管理员仍可以改用户。
- 平台尚未在真实环境长期运行；与集群无关的用户管理行为已在演示环境与单元测试中验证，命令行与 systemd 相关行为以真实部署联调为准。

## 常见问题与注意

- **我看不到「用户管理」菜单？** 你的角色既没有 users.manage 也没有 audit.view。找管理员；或确认当前登录的账号对不对（右上角显示用户名与角色）。
- **按钮灰色？** 悬停看原因：没有 users.manage（审计员只读）、目标是自己、该用户没有绑定 MFA、该用户当前未被锁定。
- **用户说「用户名或口令错误」，但我确认口令对？** 登录页只认用户名 + 口令，这条提示只可能是：用户名不存在（或输错大小写以外的字符）、口令错、账号被禁用（登录页不区分原因）。先看列表里的状态。
- **用户说「登录失败次数过多」？** 看列表状态是「已锁定」就点「解锁」；是「正常」说明是 IP 维度的锁，等待最长 10 分钟。
- **用户丢了手机？** 只影响提交生产高风险变更，不影响登录。「重置 TOTP」，让他登录后重新绑定。
- **用户忘了口令？** 「重置口令」，用安全渠道发新口令，让他自己改。平台不支持邮件找回。
- **想让某人短暂拥有某权限？** 平台没有「临时授权」。可以改角色，用完再改回去，每次改动都会写审计、吊销会话。
- **为什么我改了角色，列表里没变化？** 如果你勾了管理员，变更是提案，确认前角色保持不变，去「权限与审计」→「待确认提案」看进度。
- **提案没人确认怎么办？** 60 分钟自动作废；重新发起，或让另一名管理员尽快处理。只有一名管理员时见「四、授予管理员」前置条件。
- **能把用户批量导入吗？** 不能，目前只能逐个新建（或用命令行逐个）。
- **在哪里看到谁改了用户？** 「权限与审计」→「审计日志」，动作筛选里选 `user.add` `user.roles` 等（审计页的动作候选来自已有记录，做过之后才会出现）。
- **在帮助里看到的演示账号（admin、dba、sre 等）是什么？** 那是用 `--dev-seed` 启动的演示环境预置的账号，口令公开，仅用于演示；正式环境没有这些账号。

## 已知限制与易混淆点

核对于代码与演示环境，格式为「界面 / 文档写的是 A，实际是 B」。

| 界面 / 文档写的是 | 实际是 | 建议 |
|---|---|---|
| 新建抽屉里「用户名（字母 / 数字 / . _ -）」，输入框最多 40 个字符 | 后端规则是 2–64 位、小写字母 / 数字 / `.` `_` `@` `-`，大写自动转小写；`@` 也允许，但页面输入框限制了 40 位 | 以后端规则为准，用户名尽量短、全小写 |
| 「部门」输入框允许 60 个字，邮箱框允许 100 位 | 后端部门最多 40 个字，邮箱最多 120 位 | 部门不要超过 40 个字 |
| 「最终权限 = 所有角色能力的并集」 | 准确说是每项能力取**最强**的授予方式（允许 > 需审批 > 范围内），不是简单并集 | 见「先搞清几个概念」 |
| 「所有环境（默认）」与具体环境像是叠加 | 具体环境一旦「单独设置」就**完全覆盖**所有环境；单独设置却不选角色则该环境没有任何角色 | 按「角色按环境分配」的举例核对 |
| 在某环境给用户设置了角色 | 用户在**每个集群**里按**该集群的环境**取角色；其他环境行的角色对当前集群不起作用，该环境的集群才受影响。没有任何环境行给他角色的集群，对他不可见 | 想让他能用哪个集群，就在该集群的环境上给角色；环境与集群的对应见「环境对应哪些集群、谁能看到哪个集群」 |
| 用户管理、角色权限页像是每个集群各一套 | 它们是全局的，授权按**主集群的环境**：管理员只在非主集群的环境里有角色时，管不了用户、角色与集群接入 | 管理员设在「所有环境」 |
| 不能禁用 / 删除 / 重置自己、不能改自己的角色 | 这些只是页面按钮置灰；后端只强制「最后一名管理员不能被删除 / 禁用 / 降级」 | 不要依赖它做安全边界，通过流程约束管理员 |
| 「授予管理员需要另一名管理员确认」 | 只管页面与接口；命令行 `user add --role admin` 直接生效，不写审计 | 限制中控机登录权限，必要时核对 `users.json` |
| 本页的「重置 TOTP」像是可以让用户立即重新绑定 | 绑定只能用户自己登录后在「我的账号」完成，管理员不能代绑；重新绑定前该用户无法提交生产高风险变更（登录不受影响） | 通知用户 |
| 「重置口令」后用户拿到新口令即可 | 没有「首次登录强制改口令」功能，新口令会一直有效直到用户自己改 | 要求用户立即修改 |
| 「解锁」按钮看起来能解决一切登录被拒 | 只清用户名维度；IP 维度的锁、已禁用都不是它能解决的；用户列表也看不到 IP 维度锁 | 见「八、解锁」 |
| 部分旧说明写「审计员账号拿不到用户列表」 | 实际上有 audit.view 的账号（审计员、审批人）**可以**读到用户列表（含邮箱 / 手机），只是写不了；没有 users.manage 和 audit.view 才被 403 | 以本篇「谁能看到」表为准；用户资料里的邮箱 / 手机对审计员可见，注意保护 |
| 自己行的按钮提示「不能对自己的账号执行该操作（改自己的口令 / MFA 请到「权限与审计 → 我的账号」）」 | 该提示只出现在「重置口令」上；「重置 TOTP」对自己**没有**页面限制（已绑定时可点）。而「我的账号」里没有重置 MFA 的按钮，只写「如需重置，请联系管理员（用户管理 → 重置 TOTP）」 | 管理员自己丢了认证器：可由另一名管理员重置，或自己在本页重置后重新绑定 |
| 命令行 `user` 与页面功能对等 | 命令行没有删除 / 解锁 / 改资料 / 改角色；运行中的服务读不到命令行的改动，甚至可能把它覆盖 | 停服务后再操作，或只用页面 |
| 删除用户后「历史审计保留」 | 保留的是文字记录（用户名），不是账号；同名重建的新账号在审计里与旧账号无法区分 | 不复用已删除的用户名 |
| 「最近登录」是实时的 | 服务端为减少写盘，30 秒内重复登录只更新内存；页面每 9 秒左右刷新一次 | 偏差在秒级，可忽略 |

## 官方参考

以下链接均已打开核实（页面存在且内容与所述一致）。本篇讲的是**平台自己的账号**；TiDB 数据库自身的用户与权限请参考这些页面。页面以 stable 为准，**以你集群的版本为准**，必要时把地址里的 stable 换成对应版本（如 v8.1）。

- [用户账户管理](https://docs.pingcap.com/zh/tidb/stable/user-account-management)：TiDB 的用户由「用户名 + 主机」组成，存放在 `mysql.user` 表；说明 `CREATE USER`、修改口令、`DROP USER` 以及忘记 root 口令的处理。与本平台用户互不相通。

- [权限管理](https://docs.pingcap.com/zh/tidb/stable/privilege-management)：`GRANT` / `REVOKE` / `SHOW GRANTS`，静态权限与动态权限，权限存放的系统表。
- [CREATE USER](https://docs.pingcap.com/zh/tidb/stable/sql-statement-create-user)：数据库用户的创建语句，支持口令、TLS 要求、账号锁定等选项。
- [CREATE ROLE](https://docs.pingcap.com/zh/tidb/stable/sql-statement-create-role)：数据库角色的创建语句。
